## Warum startet das Dashboard nicht, und was steht im Log?

<!-- abschnitt: prio=A; gewicht=20; readme=missing; cluster=dashboard-01; features=dashboard-pillow-version,dashboard-version-select,migration-pinned-versions,dashboard-enable -->
<!-- muss beantworten: Startprotokoll und Log lesen, die typischen Meldungen und was jeweils hilft, feste ESPHome-Version mit Auto Detect für Pillow und Device Builder. -->

Den Grund zeigt das Startprotokoll im ESPHome-Tab, dieselben Meldungen stehen im Log der Instanz. Meist lässt sich die gewählte Version nicht installieren. Dann hilft eine feste ESPHome-Version wie `2026.6.5` und „Auto Detect“ bei Pillow und Device Builder.
<!-- quelle: code=src/lib/dashboard.ts:248-265@v2.0.0-beta.2; code=admin/jsonTab.json5:44-73@v2.0.0-beta.2; code=io-package.json:187-189@v2.0.0-beta.2; forum=1315239; forum=1332264 -->

| Meldung | Bedeutung | Was du tust |
|---|---|---|
| „Fatal error starting ESPHomeDashboard“ | Die Installation ist gescheitert, oft wegen einer Versionskombination, die pip nicht auflösen kann. | Versionen wie unten zurückstellen. |
| „ESPHome Dashboard could not be started, "…" is missing in the Python environment“ | Die Python-Umgebung ist unvollständig. | Python-Umgebung zurücksetzen, siehe [unten](#clear-autopy-cache-if-python). |
| „ESPHome Dashboard stopped (exit code …)“ | Das Dashboard ist nach dem Start beendet worden. | Die `[ESPHome - Console]`-Zeilen davor nennen den Grund, siehe [nächster Abschnitt](#log-only-say-esphome-dashboard). |
| „ESPHome Dashboard container … was not created“ | Docker fehlt, läuft nicht oder das Image ließ sich nicht laden. | Docker prüfen oder „Docker-Integration verwenden (Beta)“ ausschalten. |
<!-- quelle: code=src/lib/dashboard.ts:587-591@v2.0.0-beta.2; code=src/lib/dashboard.ts:658-683@v2.0.0-beta.2; code=src/lib/dashboard.ts:802-808@v2.0.0-beta.2; forum=1126697; forum=1221563 -->

### So gehst du vor

1. Öffne die Instanz-Einstellungen, Reiter „ESPHome-Dashboard“.
2. Stell „ESPHome Dashboard-Version“ auf `2026.6.5` oder auf die Version, die zuletzt lief.
3. Stell unter „Fortschrittlich“ „Pillow-Version“ und „ESPHome Device Builder-Version“ auf „Auto Detect“.
4. Speichere. Die Instanz startet neu und installiert die Versionen.
5. Es hat geklappt, wenn das Startprotokoll „ESPHome Dashboard is reachable on port …“ zeigt und das Dashboard im Tab erscheint.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=admin/jsonConfig.json5:538-562@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:88-107@v2.0.0-beta.2; code=src/lib/dashboard.ts:1182-1183@v2.0.0-beta.2; forum=1317187; forum=1322645 -->

Startet es dann immer noch nicht, ist oft die Python-Umgebung beschädigt, etwa nach einem abgebrochenen Download: [Wie setze ich die Python-Umgebung zurück?](#clear-autopy-cache-if-python)
<!-- quelle: code=src/lib/dashboard.ts:1090-1108@v2.0.0-beta.2; forum=1237549; forum=1254323 -->

**Siehe auch:** [Wie wähle oder aktualisiere ich die ESPHome-Dashboard-Version?](../02.anleitungen/03.dashboard-nutzen.md#choose-update-esphome-dashboard-version)

## Was tun bei "Please install the pillow python package"?

<!-- abschnitt: prio=B; gewicht=8; readme=partial; cluster=dashboard-02; features=dashboard-pillow-version,dashboard-enable,dashboard-clear-autopy-cache -->
<!-- muss beantworten: Pillow-Version auf Auto Detect stellen, sonst Python-Umgebung zurücksetzen und Instanz neu starten. -->

Installier nichts am System. Das Dashboard läuft in der eigenen Python-Umgebung des Adapters und sieht kein Pillow, das du per Paketverwaltung oder pip installierst.
<!-- quelle: code=src/lib/dashboard.ts:540-591@v2.0.0-beta.2; forum=1080009; forum=1270881; issue=#188 -->

1. Öffne im Reiter „ESPHome-Dashboard“ den Bereich „Fortschrittlich“.
2. Stell „Pillow-Version“ auf „Auto Detect“. Dann installiert der Adapter das Pillow, das zur gewählten ESPHome-Version passt. Eine feste Version muss zu ESPHome passen, sonst fehlt Pillow.
3. Speichere. Die Instanz startet neu und richtet die Umgebung ein.
4. Kommt die Meldung weiter, setz die Python-Umgebung zurück.
<!-- quelle: code=admin/jsonConfig.json5:538-550@v2.0.0-beta.2; code=io-package.json:188@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:40-56@v2.0.0-beta.2; forum=633144; forum=726998 -->

Mit „Docker-Integration verwenden (Beta)“ gibt es das Feld nicht, dort bringt das ESPHome-Image Pillow selbst mit.
<!-- quelle: code=admin/jsonConfig.json5:548@v2.0.0-beta.2; code=README.md:231-233@v2.0.0-beta.2 -->

**Siehe auch:** [Python-Umgebung zurücksetzen](#clear-autopy-cache-if-python) · [Dashboard-Version wählen](../02.anleitungen/03.dashboard-nutzen.md#choose-update-esphome-dashboard-version)

## Warum stoppt das Dashboard nach einer neuen ESPHome-Version?

<!-- abschnitt: prio=A; gewicht=9; readme=missing; cluster=dashboard-04; features=dashboard-version-select,dashboard-pillow-version,migration-pinned-versions,dashboard-enable,logging-misc-messages -->
<!-- muss beantworten: Grund im Log mit [ESPHome - Console] finden, auf die zuletzt laufende Version zurückstellen, Pillow auf Auto Detect. -->

Die neue Version lässt sich auf deinem System nicht installieren oder starten. Den Grund schreibt der Adapter als Fehler mit `[ESPHome - Console]` ins Log, direkt vor „ESPHome Dashboard stopped (exit code …)“. Stell die Version zurück, die zuletzt lief.
<!-- quelle: code=src/lib/dashboard.ts:644-661@v2.0.0-beta.2; issue=#463; issue=#479; forum=1351814 -->

### So gehst du vor

1. Öffne die Instanz-Einstellungen, Reiter „ESPHome-Dashboard“.
2. Steht bei „ESPHome Dashboard-Version“ „Always last available“ oder die neue Version, trag die Version ein, die zuletzt lief, oder `2026.6.5`.
3. Prüfe unter „Fortschrittlich“, dass „Pillow-Version“ auf „Auto Detect“ steht.
4. Speichere. Die Instanz startet neu und installiert die Version. Das dauert einige Minuten.
5. Es hat geklappt, wenn danach kein „ESPHome Dashboard stopped“ mehr im Log folgt.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=admin/jsonConfig.json5:538-550@v2.0.0-beta.2; code=src/lib/dashboard.ts:405-413@v2.0.0-beta.2; forum=1349300; forum=1301427 -->

Normale Meldungen des Dashboards stehen nur auf Protokollstufe „debug“ im Log. Fehler erscheinen immer.
<!-- quelle: code=src/lib/dashboard.ts:644-656@v2.0.0-beta.2 -->

**Siehe auch:** [Wie wähle oder aktualisiere ich die ESPHome-Dashboard-Version?](../02.anleitungen/03.dashboard-nutzen.md#choose-update-esphome-dashboard-version)

## Wie setze ich die Python-Umgebung zurück, wenn sie defekt ist?

<!-- abschnitt: prio=B; gewicht=7; readme=missing; cluster=dashboard-06; features=dashboard-clear-autopy-cache,info-clear-autopy-button,dashboard-enable -->
<!-- muss beantworten: Button "Python-Umgebung zurücksetzen" unter dem Dashboard-Reiter, danach Instanz neu starten; ESPHome wird neu installiert, YAML-Dateien bleiben; bei Docker-Integration nicht sichtbar. -->

Mit „Python-Umgebung zurücksetzen“ löschst du die Python-Umgebung des Dashboards mit ESPHome, Device Builder, Pillow und allem, was dazugehört. Deine YAML-Dateien bleiben erhalten.
<!-- quelle: code=src/lib/dashboard.ts:1091-1108@v2.0.0-beta.2; code=admin/i18n/de.json:24@v2.0.0-beta.2; forum=1115918; forum=1315078 -->

1. Öffne die Einstellungen der Instanz, Reiter „ESPHome-Dashboard“. Die Instanz muss laufen.
2. Klick auf „Python-Umgebung zurücksetzen“ und bestätige.
3. Start die Instanz neu. Sie baut die Umgebung beim Start neu auf. Das braucht Internet und dauert einige Minuten.
<!-- quelle: code=admin/jsonConfig.json5:465-490@v2.0.0-beta.2; code=src/lib/dashboard.ts:1100-1102@v2.0.0-beta.2; code=src/lib/dashboard.ts:572-583@v2.0.0-beta.2 -->

Geklappt hat es, wenn im Log `Starting ESPHome Dashboard` steht und der Tab „ESPHome“ das Dashboard zeigt. Statt des Knopfs kannst du auch `esphome.0.info.clearAutopyCache` auf `true` setzen.
<!-- quelle: code=src/lib/dashboard.ts:625-627@v2.0.0-beta.2; code=src/main.ts:206-217@v2.0.0-beta.2; code=src/main.ts:1747-1752@v2.0.0-beta.2; issue=#176; issue=#191 -->

Mit „Docker-Integration verwenden (Beta)“ ist der Knopf ausgeblendet, dort gibt es keine Python-Umgebung.
<!-- quelle: code=admin/jsonConfig.json5:473@v2.0.0-beta.2 -->

## Was tun bei Permission denied oder fehlendem YAML-Ordner?

<!-- abschnitt: prio=B; gewicht=6; readme=missing; cluster=dashboard-07; features=yaml-directory,dashboard-enable,yaml-upload -->
<!-- muss beantworten: Den Ordner legt der Adapter selbst an; Rechte am Datenverzeichnis mit "iobroker fix" korrigieren; Fehlermeldung steht im Startprotokoll des Dashboards bzw. beim Hochladen. -->

Den Ordner `iobroker-data/esphome.<Instanz>` legt der Adapter selbst an, beim Start des Dashboards und beim ersten Hochladen einer YAML-Datei. Einen fehlenden Ordner musst du nicht anlegen.
<!-- quelle: code=src/lib/dashboard.ts:595-609@v2.0.0-beta.2; code=src/lib/dashboard.ts:752-753@v2.0.0-beta.2; code=src/lib/yamlFileManager.ts:375-381@v2.0.0-beta.2; issue=#128 -->

„Permission denied“ heißt, dass Dateien oder Ordner einem anderen Benutzer gehören als dem, unter dem ioBroker läuft, z. B. nach dem Kopieren als `root` oder nach einer Wiederherstellung. Die Meldung steht im Startprotokoll im Tab „ESPHome“ oder beim Hochladen im Reiter „YAML-Dateien“.
<!-- quelle: code=src/lib/dashboard.ts:639-656@v2.0.0-beta.2; code=src/lib/yamlFileManager.ts:391-398@v2.0.0-beta.2; forum=1140567; issue=#168 -->

1. Führ in der Konsole `iobroker fix` aus. Das gibt die Dateien dem ioBroker-Benutzer zurück.
2. Start die Instanz neu.
<!-- quelle: forum=648861 -->

Setz keine Rechte mit `chmod 777`.
