## Wie zeige ich Geräte in VIS an, setze Zeiten und liste alle Geräte im Skript auf?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-29; features=state-id-scheme,entity-switch -->
<!-- muss beantworten: Datenpunkt-Pfad aufbauen, per Selektor alle Geräte finden und Werte in VIS schreiben. -->

Der Adapter liefert keine fertige Oberfläche, nur Datenpunkte. Die nutzt du in VIS, in Skripten und in Zeitplänen wie jeden anderen Datenpunkt. Ein Pfad sieht so aus: `esphome.0.<Gerät>.<Typ>.<Schlüssel>.state`.
<!-- quelle: code=src/main.ts:591-627@v2.0.0-beta.2; code=src/main.ts:952-985@v2.0.0-beta.2; forum=1245125; forum=1119031 -->

Alle Geräte findest du im Skript über ihren Online-Datenpunkt. Der Anzeigename steht im Geräteobjekt:

```javascript
$('state[id=esphome.0.*.info._online]').each(id => {
    const device = id.split('.')[2];
    log(`${getObject(`esphome.0.${device}`).common.name}: ${getState(id).val}`);
});
```
<!-- quelle: code=src/main.ts:513-533@v2.0.0-beta.2; code=src/main.ts:2011-2039@v2.0.0-beta.2 -->

Zeitgesteuert schaltest du, indem ein Zeitplan den Datenpunkt schreibt:

```javascript
schedule('0 7 * * *', () => {
    setState('esphome.0.<Gerät>.Switch.<Schlüssel>.state', true);
});
```
<!-- quelle: code=src/main.ts:1770-1775@v2.0.0-beta.2; forum=1215708 -->

<a id="use-esphome-datapoints-aliases-alexa"></a>

## Wie verwende ich ESPHome-Datenpunkte in Aliasen, Alexa oder dem IoT-Adapter?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-15; features=entity-number,state-roles-metadata -->
<!-- muss beantworten: Alias mit passenden Rollen; die Adapter-Rollen sind überwiegend generisch, Cover-Position ist schon 0 bis 100. -->

Die meisten Datenpunkte des Adapters haben die allgemeine Rolle `state`. Alexa und der IoT-Adapter erkennen sie daran nicht als Lampe, Rollo oder Thermostat. Leg deshalb einen Alias an, z. B. im Adapter „Geräte“, und verknüpf ihn mit dem ESPHome-Datenpunkt.
<!-- quelle: code=src/main.ts:1310@v2.0.0-beta.2; code=src/lib/stateAttr.ts:18-97@v2.0.0-beta.2; forum=1352068; issue=#148 -->

Einige Datenpunkte haben schon eine passende Rolle:

| Datenpunkt | Rolle |
|---|---|
| Cover `position` (0 bis 100 %) | `level.blind` |
| Cover `tilt` (0 bis 100 %) | `level.tilt` |
| Button `SET`, Cover `stop` | `button` |
| Lock `state` / `command` | `sensor.lock` / `level.lock` |
| `info._online` | `indicator.reachable` |
<!-- quelle: code=src/lib/stateAttr.ts:18-65@v2.0.0-beta.2; code=src/lib/stateAttr.ts:144-150@v2.0.0-beta.2; code=src/main.ts:723-748@v2.0.0-beta.2 -->

Soll ein Zahlenwert im Alias als An/Aus erscheinen, nutz im Alias eine Lese- und eine Schreibfunktion, z. B. `val == 60` und `val ? 60 : -5`. Die Einheit übernimmt der Adapter aus `unit_of_measurement` der YAML. Fehlt sie, rechnet Alexa eventuell falsch; trag sie dann in der YAML nach.
<!-- quelle: code=src/main.ts:576-578@v2.0.0-beta.2; forum=1352068; forum=1233149 -->

<a id="send-text-values-esphome-display"></a>

## Wie schicke ich Text oder Werte auf ein ESPHome-Display?

<!-- abschnitt: prio=A; gewicht=12; readme=missing; cluster=entities-scripts-16; features=entity-text,entity-number,entity-switch -->
<!-- muss beantworten: Text- und Number-Entitäten der YAML anlegen, Datenpunkt beschreiben, Display liest die Entität. -->

Leg in der YAML eine Text-Entität (`text:`) für Texte und eine Number-Entität (`number:`) für Zahlen an und gib sie im Display-Lambda aus. In ioBroker schreibst du `esphome.0.<Gerät>.Text.<Schlüssel>.state` oder `esphome.0.<Gerät>.Number.<Schlüssel>.state`, der Adapter schickt den Wert an das Gerät.
<!-- quelle: code=src/main.ts:768-775@v2.0.0-beta.2; code=src/main.ts:1799-1810@v2.0.0-beta.2; issue=#103; issue=#141 -->

Nimm für Texte eine Text-Entität, keinen Text-Sensor (`text_sensor:`). Dessen Datenpunkt lässt sich zwar beschreiben, der Wert geht aber nicht an das Gerät.
<!-- quelle: code=src/main.ts:760-762@v2.0.0-beta.2; code=src/main.ts:1700-1860@v2.0.0-beta.2 -->

### So gehst du vor

1. Ergänze die YAML um eine Text- und bei Bedarf eine Number-Entität, beide mit `optimistic: true` und einer `id`.
2. Gib die Werte im `lambda` deines Displays aus.
3. Spiel die Firmware auf und warte, bis sich der Adapter neu verbunden hat. Unter `esphome.0.<Gerät>.Text` und `esphome.0.<Gerät>.Number` erscheinen die neuen Entitäten.
4. Schreib deinen Text in `Text.<Schlüssel>.state` oder deine Zahl in `Number.<Schlüssel>.state`. Das Display zeigt den Wert beim nächsten Neuzeichnen.
<!-- quelle: code=src/main.ts:768-775@v2.0.0-beta.2; code=src/main.ts:1799-1810@v2.0.0-beta.2; extern=esphome.io/components/text/template; extern=esphome.io/components/number/template -->

```yaml
text:
  - platform: template
    name: "Display Text"
    id: display_text
    optimistic: true
    mode: text
    max_length: 64

number:
  - platform: template
    name: "Display Wert"
    id: display_wert
    optimistic: true
    min_value: -50
    max_value: 100
    step: 0.1

display:
  - platform: <deine Display-Plattform>
    lambda: |-
      it.printf(0, 0, id(meine_schrift), "%s", id(display_text).state.c_str());
      it.printf(0, 20, id(meine_schrift), "%.1f", id(display_wert).state);
```
<!-- quelle: extern=esphome.io/components/text/template; extern=esphome.io/components/number/template; extern=esphome.io/components/display -->

<!-- bild: Objektbaum mit Text.<Schlüssel>.state und Number.<Schlüssel>.state eines Display-Geräts -->

Den Wert eines anderen Adapters, z. B. eine Temperatur, kopierst du per Skript in den ESPHome-Datenpunkt. Die Länge eines Textes prüft der Adapter nicht, halte dich an `max_length` aus der YAML.
<!-- quelle: code=src/main.ts:1806-1810@v2.0.0-beta.2; forum=632606 -->

```javascript
on({ id: '<Adapter>.0.<Sensor>.TEMPERATURE', change: 'ne' }, obj => {
    setState('esphome.0.<Gerät>.Number.<Schlüssel>.state', obj.state.val);
});
setState('esphome.0.<Gerät>.Text.<Schlüssel>.state', 'Müll: Dienstag');
```
<!-- quelle: code=src/main.ts:1799-1810@v2.0.0-beta.2; forum=632606 -->

## Wie steuere ich einen Servo oder Ausgang eines ESPHome-Geräts?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=entities-scripts-23; features=entity-number,entity-switch -->
<!-- muss beantworten: Servo/PCA9685 als Number oder Output in der YAML, Wert über den Datenpunkt setzen. -->

Einen Servo oder einen einzelnen Ausgang meldet ESPHome nicht über die API, deshalb gibt es dafür keinen Datenpunkt. Leg in der YAML eine Entität an, die ihn steuert, meist eine Template-Number. Ihren Wert schreibst du dann in ioBroker.
<!-- quelle: code=src/main.ts:704-813@v2.0.0-beta.2; forum=600295 -->

```yaml
number:
  - platform: template
    name: "Servo"
    min_value: -100
    max_value: 100
    step: 1
    optimistic: true
    set_action:
      - servo.write:
          id: my_servo
          level: !lambda "return x / 100.0;"
```
<!-- quelle: extern=esphome.io/components/servo -->

Nach dem Flashen steht in ioBroker `esphome.0.<Gerät>.Number.<Schlüssel>.state`. Schreib dort z. B. `50`, und der Servo fährt auf die Position. Für einen Ausgang nimmst du entsprechend einen Template-Switch oder eine Lampe mit `platform: monochromatic`.
<!-- quelle: code=src/main.ts:1799-1804@v2.0.0-beta.2; extern=esphome.io/components/switch/template -->

## Wie erkenne ich Anwesenheit per Bluetooth-Beacon oder Smartwatch?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=entities-scripts-26; features=entity-sensor -->
<!-- muss beantworten: RSSI-Sensor in ESPHome, Schwellwert und Verzögerung im Skript, damit "weg" erkannt wird. -->

Ein ESP32 misst mit dem Sensor `ble_rssi` die Signalstärke eines Beacons oder einer Uhr. In ioBroker erscheint der Wert als `esphome.0.<Gerät>.Sensor.<Schlüssel>.state` in dBm.
<!-- quelle: code=src/main.ts:756-758@v2.0.0-beta.2; code=src/main.ts:952-985@v2.0.0-beta.2; forum=1038053 -->

```yaml
esp32_ble_tracker:

sensor:
  - platform: ble_rssi
    mac_address: "<MAC des Beacons>"
    name: "Beacon RSSI"
```
<!-- quelle: extern=esphome.io/components/sensor/ble_rssi -->

Der Wert ändert sich nur, solange der ESP das Beacon empfängt. Ist es weg, bleibt der letzte Wert stehen. „Abwesend“ erkennst du deshalb im Skript an einer Pause:

```javascript
let timer;
on({ id: 'esphome.0.<Gerät>.Sensor.<Schlüssel>.state', change: 'any' }, () => {
    setState('0_userdata.0.anwesend', true);
    clearTimeout(timer);
    timer = setTimeout(() => setState('0_userdata.0.anwesend', false), 60000);
});
```

## Wie nutze ich bei einer RGBW-Lampe den Weißkanal automatisch?

<!-- abschnitt: prio=B; gewicht=2; readme=covered; cluster=entities-scripts-07; features=light-rgb-auto-white,entity-light -->
<!-- muss beantworten: rgbAutoWhite im config-Ordner; #ffffff schaltet auf den Weißkanal; ohne „Konfigurationszustände anzeigen“ steht es nach jeder neuen Verbindung wieder auf false. -->

Bei Lampen mit eigenem Weißkanal legt der Adapter `esphome.0.<Gerät>.Light.<Schlüssel>.config.rgbAutoWhite` an, Standard `false`. Setz es auf `true`.
<!-- quelle: code=src/main.ts:1117-1146@v2.0.0-beta.2; code=README.md:479-495@v2.0.0-beta.2; issue=#15 -->

Danach gilt beim Schreiben von `colorHEX`:

- `#ffffff` schaltet Rot, Grün und Blau aus und den Weißkanal voll an.
- Jede andere Farbe schaltet den Weißkanal aus und setzt die Farbe.
<!-- quelle: code=src/main.ts:1930-1943@v2.0.0-beta.2; forum=591191 -->

Derzeit hält die Einstellung nur, wenn „Konfigurationszustände anzeigen“ an ist. Ist die Option aus, steht `rgbAutoWhite` nach jeder neuen Verbindung wieder auf `false`. Schalte die Option deshalb ein, wenn du `rgbAutoWhite` nutzt.
<!-- quelle: code=src/main.ts:632-646@v2.0.0-beta.2; code=src/main.ts:1117-1146@v2.0.0-beta.2; interview=27 -->
