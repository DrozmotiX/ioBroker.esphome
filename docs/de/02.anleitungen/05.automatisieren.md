<a id="send-text-values-esphome-display"></a>

## Wie schicke ich Text oder Werte auf ein ESPHome-Display?

<!-- abschnitt: prio=A; gewicht=12; readme=missing; cluster=entities-scripts-16; features=entity-text,entity-number,entity-switch -->
<!-- muss beantworten: Text- und Number-Entitäten der YAML anlegen, Datenpunkt beschreiben, Display liest die Entität. -->

**Kurz:** Lege in der YAML eine Text-Entität (`text:`) für Texte und eine Number-Entität (`number:`) für Zahlen an und zeige sie im Display-Lambda an. In ioBroker schreibst du dann `esphome.0.<Gerät>.Text.<Schlüssel>.state` oder `esphome.0.<Gerät>.Number.<Schlüssel>.state`, der Adapter schickt den Wert an das Gerät.
<!-- quelle: code=main.js:1018-1025@v1.0.1; code=main.js:2367-2380@v1.0.1; issue=#103; issue=#141 -->

**Ab v0.6.2** unterstützt der Adapter Text-Entitäten ([#141](https://github.com/DrozmotiX/ioBroker.esphome/issues/141), [#103](https://github.com/DrozmotiX/ioBroker.esphome/issues/103)). Ältere Antworten im Forum empfehlen einen Umweg über MQTT mit `mqtt_subscribe`. Den brauchst du seitdem nicht mehr.
<!-- quelle: issue=#141; issue=#103; forum=867678; forum=677645 -->

### So gehst du vor

1. Ergänze die YAML um eine Text- und, falls nötig, eine Number-Entität. Beide brauchen `optimistic: true`, damit das Gerät Werte von außen übernimmt. Gib ihnen eine `id`, damit das Display sie lesen kann.
2. Gib die Werte im `lambda` deines Displays aus.
3. Spiele die Firmware auf und warte, bis sich der Adapter neu verbunden hat. Unter `esphome.0.<Gerät>.Text` und `esphome.0.<Gerät>.Number` erscheinen neue Ordner mit einer Zahl; ihr Name aus der YAML steht als Name des Ordners.
4. Schreibe deinen Text in `Text.<Schlüssel>.state` oder deine Zahl in `Number.<Schlüssel>.state`. Das Display zeigt den Wert beim nächsten Neuzeichnen.
<!-- quelle: code=main.js:1018-1025@v1.0.1; code=main.js:2367-2380@v1.0.1; extern=esphome.io/components/text/template; extern=esphome.io/components/number/template -->

```yaml
text:
  - platform: template
    name: "Display Text"
    id: display_text
    optimistic: true
    mode: text
    max_length: 64

number:
  - platform: template
    name: "Display Wert"
    id: display_wert
    optimistic: true
    min_value: -50
    max_value: 100
    step: 0.1

display:
  - platform: <deine Display-Plattform>
    # weitere Einstellungen deines Displays wie bisher
    lambda: |-
      it.printf(0, 0, id(meine_schrift), "%s", id(display_text).state.c_str());
      it.printf(0, 20, id(meine_schrift), "%.1f", id(display_wert).state);
```
<!-- quelle: extern=esphome.io/components/text/template; extern=esphome.io/components/number/template; extern=esphome.io/components/display -->

<!-- bild: Objektbaum mit Text.<Schlüssel>.state und Number.<Schlüssel>.state eines Display-Geräts -->

### Werte aus einem anderen Adapter anzeigen

Einen Wert aus einem anderen Adapter, z. B. eine Temperatur, kopierst du per Skript in den ESPHome-Datenpunkt. Ein eigenes Gegenstück zur Home-Assistant-Sensorplattform (`platform: homeassistant`) hat der Adapter nicht.
<!-- quelle: forum=632606; issue=#141 -->

```javascript
on({ id: '<Adapter>.0.<Sensor>.TEMPERATURE', change: 'ne' }, obj => {
    setState('esphome.0.<Gerät>.Number.<Schlüssel>.state', obj.state.val);
});

// Text zusammensetzen
setState('esphome.0.<Gerät>.Text.<Schlüssel>.state', 'Müll: Dienstag');
```
<!-- quelle: code=main.js:2367-2380@v1.0.1; forum=632606 -->

Mit einem Template-`switch` kannst du zusätzlich etwas ein- und ausblenden, z. B. die Hintergrundbeleuchtung. Den schaltest du über `esphome.0.<Gerät>.Switch.<Schlüssel>.state` mit `true` oder `false`.
<!-- quelle: code=main.js:1014-1016@v1.0.1; code=main.js:2339-2344@v1.0.1 -->

> [!IMPORTANT]
> Nimm für Texte aus ioBroker eine Text-Entität (`text:`), keinen Text-Sensor (`text_sensor:`). Der Datenpunkt eines Text-Sensors ist in v1.0.1 zwar beschreibbar, der Adapter schickt den Wert aber nicht an das Gerät und er bleibt unbestätigt (`ack = false`). Das ist eine bekannte Einschränkung.
<!-- quelle: code=main.js:1010-1012@v1.0.1; code=main.js:2308-2555@v1.0.1 -->
<!-- issue: A15 -->

> [!NOTE]
> Der Adapter prüft die Länge eines Textes nicht. Halte dich an `max_length` aus der YAML, sonst entscheidet die Firmware, was mit dem zu langen Text passiert.
<!-- quelle: code=main.js:2374-2380@v1.0.1 -->
