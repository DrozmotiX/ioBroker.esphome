## Warum öffnet sich der Dashboard-Tab nicht ("localhost verweigert die Verbindung")?

<!-- abschnitt: prio=A; gewicht=13; readme=partial; cluster=dashboard-11; features=dashboard-enable,dashboard-url-admin-tab,admin-tab-link,migration-dashboard-url -->
<!-- muss beantworten: Dashboard-IP und Port korrekt eintragen (ohne ":6052" im IP-Feld), nicht 127.0.0.1 für Zugriff von außen, URL-Feld zuletzt bearbeiten. -->

**Kurz:** Trag bei „IP-Adresse, unter der ESPHome Dashboard zur Integration in ioBroker Admin ausgeführt wird“ die IP-Adresse deines ioBroker-Rechners ein, ohne Port. Nimm nicht `127.0.0.1` oder `localhost`, wenn du den Admin von einem anderen Rechner aus öffnest.
<!-- quelle: code=admin/jsonConfig.json5:640-650@v1.0.1; code=admin/jsonConfig.json5:744-757@v1.0.1; forum=1340972; forum=1274190 -->

Der Dashboard-Tab im Admin ist nur ein Fenster auf die Adresse unter „URL des ESPHome-Dashboards“. Diese Adresse lädt dein **Browser**, nicht der ioBroker-Rechner. `localhost` oder `127.0.0.1` zeigt deshalb auf den Rechner, an dem du gerade sitzt. Läuft dort kein Dashboard, meldet der Browser „localhost verweigert die Verbindung“.
<!-- quelle: code=io-package.json:153-158@v1.0.1; issue=#98 -->

### So gehst du vor

1. Öffne die Instanz-Einstellungen von ESPHome und dort den Reiter „ESPHome-Dashboard“.
2. Setze den Haken bei „ESPHome-Dashboard aktivieren“.
3. Wähle bei „IP-Adresse, unter der ESPHome Dashboard zur Integration in ioBroker Admin ausgeführt wird“ die IP-Adresse deines ioBroker-Rechners aus der Liste, z. B. `192.168.x.y`. Schreib **keinen Port** dazu.
4. Klapp „Fortschrittlich“ auf. Bei „Port des ESPHome-Dashboards“ steht der Port, Standard ist `6052`. Ändere ihn nur, wenn der Port schon belegt ist.
5. Prüfe im selben Bereich „URL des ESPHome-Dashboards“. Dort muss `http://192.168.x.y:6052` stehen. Das Feld füllt sich aus IP und Port von selbst.
6. Speichere. Die Instanz startet neu und richtet das Dashboard ein. Beim ersten Start dauert das mehrere Minuten, weil Python und ESPHome geladen werden.
7. Öffne danach den Tab des ESPHome-Adapters im Admin-Menü links.
<!-- quelle: code=admin/jsonConfig.json5:608-650@v1.0.1; code=admin/jsonConfig.json5:726-757@v1.0.1; code=io-package.json:197-199@v1.0.1; code=main.js:389-453@v1.0.1 -->

<!-- bild: screenshot Reiter „ESPHome-Dashboard“ mit Haken, IP-Auswahl und aufgeklapptem Bereich „Fortschrittlich“ mit Port und URL -->

> [!WARNING]
> Schreib nicht `192.168.x.y:6052` in das IP-Feld. Der Adapter hängt den Port selbst an, die URL wird dann `http://192.168.x.y:6052:6052` und der Tab bleibt leer. Das gilt auch für das Beispiel `127.0.0.1:6052` im README.
<!-- quelle: code=admin/jsonConfig.json5:754@v1.0.1; interview=7 -->

> [!IMPORTANT]
> Änderst du IP oder Port, nachdem du die URL von Hand angepasst hast, überschreibt der Adapter deine URL wieder mit `http://<IP>:<Port>`. Bearbeite eine eigene URL deshalb immer zuletzt. Das ist eine bekannte Einschränkung in v1.0.1.
<!-- quelle: code=admin/jsonConfig.json5:752-756@v1.0.1; interview=7 -->
<!-- issue: A2 -->

Hast du das Dashboard mit einer Version vor v0.6.1 eingerichtet, die nur IP und Port kannte, übernimmt der Adapter beim ersten Start einmalig `http://<IP>:<Port>` in das URL-Feld und startet neu. Du musst nichts tun.
<!-- quelle: code=main.js:150-185@v1.0.1; code=CHANGELOG_OLD.md:47@v1.0.1 -->

Bleibt der Tab weiter leer, prüfe, ob das Dashboard überhaupt läuft: Im Log der Instanz muss „Starting ESPHome Dashboard“ stehen. Steht dort ein Fehler, hilft [Warum startet das Dashboard nicht?](../04.fehlerbehebung/01.dashboard-startet-nicht.md#dashboard-not-start-pillow-esphome).
<!-- quelle: code=main.js:449-450@v1.0.1 -->
