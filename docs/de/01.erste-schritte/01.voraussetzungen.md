## Muss ich Python oder pip selbst installieren?

<!-- abschnitt: prio=B; gewicht=2; readme=covered; cluster=dashboard-09; features=dashboard-enable,requirements-internet -->
<!-- muss beantworten: Der Adapter bringt seine eigene Python-Umgebung mit; du brauchst nur Node.js 22.19 oder neuer und beim ersten Dashboard-Start Internetzugang. -->

Nein. Für die Geräte braucht der Adapter kein Python. Nur das integrierte Dashboard braucht Python, und dafür legt der Adapter eine eigene Umgebung an und installiert ESPHome hinein. Ein Python oder pip auf deinem System nutzt er nicht.
<!-- quelle: code=src/main.ts:358-404@v2.0.0-beta.2; code=src/lib/dashboard.ts:540-591@v2.0.0-beta.2; forum=1243713; issue=#259 -->

Du brauchst nur Node.js 22.19 oder neuer. Beim ersten Start des Dashboards lädt der Adapter Python und die Pakete aus dem Internet, das dauert einige Minuten. Welche Python-Version er nimmt, steht unter „Fortschrittlich“ im Feld „Python-Version“, Standard ist 3.13.2.
<!-- quelle: code=package.json:29-31@v2.0.0-beta.2; code=src/lib/dashboard.ts:572-583@v2.0.0-beta.2; code=admin/jsonConfig.json5:565-580@v2.0.0-beta.2 -->

## Auf welchen Systemen und mit welcher Hardware läuft der Adapter?

<!-- abschnitt: prio=A; gewicht=13; readme=missing; cluster=dashboard-08,logs-install-14,logs-install-17,logs-install-19; features=dashboard-enable,requirements-runtime -->
<!-- muss beantworten: Welche Plattformen das integrierte Dashboard unterstützt (64-Bit-Linux, macOS), Docker als Alternative, Hardwarebedarf, wann ein externes Dashboard besser ist. -->

Der Adapter läuft auf jedem System mit ioBroker und Node.js 22.19 oder neuer. Das integrierte ESPHome-Dashboard läuft nur auf 64-Bit-Linux und macOS.
<!-- quelle: code=package.json:29-31@v2.0.0-beta.2; interview=3 -->

| Was | Voraussetzung |
|---|---|
| Adapter mit Geräten | Node.js 22.19 oder neuer, Admin 7.8.20 oder neuer, js-controller 6.0.11 oder neuer |
| Integriertes Dashboard | zusätzlich 64-Bit-Linux oder macOS und Internetzugang beim Start |
| Dashboard mit „Docker-Integration verwenden (Beta)“ | zusätzlich Docker auf dem ioBroker-Rechner |
<!-- quelle: code=package.json:29-31@v2.0.0-beta.2; code=io-package.json:171-180@v2.0.0-beta.2; code=admin/jsonConfig.json5:381-392@v2.0.0-beta.2; interview=3 -->

Für die Geräte braucht der Adapter kein Python, er spricht sie direkt über die Native API an. Python braucht nur das integrierte Dashboard. Der Adapter legt dafür beim Start eine eigene Umgebung an, standardmäßig mit Python 3.13.2.
<!-- quelle: code=src/lib/dashboard.ts:159@v2.0.0-beta.2; code=src/lib/dashboard.ts:540-583@v2.0.0-beta.2; interview=1 -->

Ein Raspberry Pi mit 64-Bit-Prozessor ist trotzdem ein 32-Bit-System, wenn das Betriebssystem in 32 Bit installiert ist. Dort startet das Dashboard erst nach einer Neuinstallation mit 64-Bit-Betriebssystem.
<!-- quelle: forum=983298; issue=#138 -->

### Welche Hardware brauche ich?

Für die Geräte reicht jede Hardware, auf der ioBroker läuft. Das Dashboard kompiliert Firmware, das braucht viel Rechenleistung und Arbeitsspeicher. Ein Raspberry Pi 3 wird dabei sehr langsam, ein Raspberry Pi 4 läuft stabil. Ist dein Rechner zu schwach oder läuft er unter Windows, betreibe das Dashboard auf einem anderen Rechner.
<!-- quelle: forum=1130028; forum=661850; interview=3; interview=4 -->

## Brauche ich Home Assistant oder MQTT, um ESPHome-Geräte in ioBroker zu nutzen?

<!-- abschnitt: prio=B; gewicht=5; readme=covered; cluster=connection-setup-02; features=requirements-esphome-api,device-add-update-sendto,state-id-scheme -->
<!-- muss beantworten: Der Adapter spricht die native ESPHome-API direkt, du brauchst weder Home Assistant noch MQTT, aber den api-Eintrag in der Geräte-YAML. -->

Nein. Der Adapter verbindet sich direkt über die Native API von ESPHome mit dem Gerät. Home Assistant und MQTT brauchst du dafür nicht.
<!-- quelle: code=src/main.ts:358-404@v2.0.0-beta.2; forum=1230025; forum=697057 -->

In der YAML des Geräts muss der Abschnitt `api:` stehen, am besten mit Verschlüsselungsschlüssel. Ohne `api:` erreicht der Adapter das Gerät nicht. Steht zusätzlich `mqtt:` in der YAML, stört das den Adapter nicht.
<!-- quelle: code=README.md:291-312@v2.0.0-beta.2; forum=566645; forum=688174 -->

```yaml
api:
  encryption:
    key: "<Schlüssel des Geräts>"
```
<!-- quelle: code=README.md:306-312@v2.0.0-beta.2 -->
