## Wie steuere ich Rollläden und Covers (auch time_based): Position, Neigung, Stopp?

<!-- abschnitt: prio=A; gewicht=9; readme=missing; cluster=entities-scripts-11,entities-scripts-12; features=entity-cover -->
<!-- muss beantworten: Position/Neigung werden in Prozent gelesen, aber 0 bis 1 geschrieben; time_based ohne Positionsrückmeldung zeigt oft 0. -->

**Kurz:** Ein Cover hat unter `esphome.0.<Gerät>.Cover.<Schlüssel>` die Datenpunkte `position`, `tilt` und `stop`. Position und Neigung werden in Prozent angezeigt, beim Schreiben erwartet der Adapter in v1.0.1 aber einen Wert von 0 bis 1: `0` = zu, `0.5` = halb offen, `1` = offen.
<!-- quelle: code=main.js:973-996@v1.0.1; code=main.js:2401-2422@v1.0.1; issue=#549; interview=17 -->

ESPHome arbeitet bei Covern mit Werten von 0 bis 1. Der Adapter multipliziert den gemeldeten Wert für die Anzeige mit 100, gibt einen geschriebenen Wert aber unverändert an das Gerät weiter. Lesen und Schreiben nutzen deshalb verschiedene Skalen.
<!-- quelle: code=main.js:974-989@v1.0.1; code=main.js:2401-2415@v1.0.1; issue=#549 -->

### Die Datenpunkte

| Datenpunkt | Anzeige | Schreiben | Rolle |
|---|---|---|---|
| `position` | 0 bis 100 % | 0 bis 1 (0 = zu, 1 = offen) | `level.blind` |
| `tilt` | 0 bis 100 % | 0 bis 1 | `level.tilt` |
| `stop` | bleibt `false` | jeder Wert hält das Cover an | `button` |
<!-- quelle: code=main.js:973-996@v1.0.1; code=main.js:2401-2422@v1.0.1; code=lib/stateAttr.js:11-35@v1.0.1 -->

Einen eigenen Datenpunkt für „Öffnen" oder „Schließen" gibt es nicht. Du öffnest mit `position` = `1` und schließt mit `position` = `0`.
<!-- quelle: code=main.js:2401-2422@v1.0.1 -->

Kann dein Cover keine Neigung, hat `tilt` keinen sinnvollen Wert. Lass den Datenpunkt dann einfach weg.
<!-- quelle: code=main.js:982-988@v1.0.1 -->

### So fährst du einen Rollladen auf eine Position

1. Öffne im Admin den Tab „Objekte" und gehe zu `esphome.0.<Gerät>.Cover`. Der Ordner mit der Zahl ist dein Cover; sein Name aus der YAML steht als Name des Ordners.
2. Schreibe in `position` den Zielwert als Bruchteil, z. B. `0.3` für 30 % offen.
3. Das Gerät fährt los und meldet seine Position zurück. Der Datenpunkt zeigt danach den Prozentwert, z. B. `30`, als bestätigten Wert (`ack = true`).
4. Zum Anhalten schreibst du `true` in `stop`.
<!-- quelle: code=main.js:974-996@v1.0.1; code=main.js:2401-2422@v1.0.1; issue=#549 -->

Im Skript:

```javascript
// Rollladen halb öffnen (in v1.0.1 Wert von 0 bis 1)
setState('esphome.0.<Gerät>.Cover.<Schlüssel>.position', 0.5);
// Anhalten
setState('esphome.0.<Gerät>.Cover.<Schlüssel>.stop', true);
```
<!-- quelle: code=main.js:2401-2422@v1.0.1 -->

> [!WARNING]
> Schreibst du einen Prozentwert wie `50` in `position`, kommt beim Gerät keine 50 % an. ESPHome rechnet mit 0 bis 1, der Rollladen fährt dann nicht auf die gewünschte Position. Das gilt genauso für `tilt`. Diese Einschränkung ist in [#549](https://github.com/DrozmotiX/ioBroker.esphome/issues/549) gemeldet.
<!-- quelle: code=main.js:2401-2415@v1.0.1; issue=#549; forum=642698; interview=17 -->

> [!TIP]
> Ein VIS-Schieberegler oder ein Sprachassistent schreibt bei der Rolle `level.blind` meist 0 bis 100. Lege dafür einen Alias an, der beim Schreiben durch 100 teilt (Schreibfunktion `val / 100`) und beim Lesen den Wert unverändert übernimmt. Dann passen beide Skalen.
<!-- quelle: code=main.js:974-989@v1.0.1; code=main.js:2401-2415@v1.0.1; issue=#549 -->

### Wenn die Position immer 0 bleibt

**Bis v0.6.1** hatte der Cover-Code einen Fehler: Die Position blieb in ioBroker bei 0 und das Cover ließ sich nicht steuern. **Ab v0.6.2** ist das behoben ([#156](https://github.com/DrozmotiX/ioBroker.esphome/issues/156)). Ein Umweg über MQTT ist seitdem nicht mehr nötig.
<!-- quelle: issue=#156; forum=608468; forum=833167; forum=1027328 -->

Seit v0.6.2 zeigt der Adapter genau die Position, die das Gerät über die API meldet. Bleibt der Wert trotzdem bei 0, kommt vom Gerät keine Position an. Der Adapter rechnet nur um, was das Gerät liefert.
<!-- quelle: code=main.js:974-980@v1.0.1; forum=608468 -->
