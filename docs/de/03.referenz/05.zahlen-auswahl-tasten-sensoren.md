## Wie sehe und schreibe ich einen ESPHome-Number (Template-Slider)?

<!-- abschnitt: prio=A; gewicht=13; readme=missing; cluster=entities-scripts-14,entities-scripts-13; features=entity-number,entity-binarysensor,entity-button,entity-unsupported -->
<!-- muss beantworten: Number ist beschreibbar; Min/Max/Step stehen nur im config-Ordner; Template-Binärsensor ist nur lesbar; unbekannte Typen. -->

Eine Number aus der YAML, z. B. ein Template-Slider, erscheint als beschreibbarer Datenpunkt `esphome.0.<Gerät>.Number.<Schlüssel>.state`. Schreibst du dort eine Zahl, schickt der Adapter sie direkt über die Native API an das Gerät.
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; forum=1007754 -->

### So schreibst du einen Number-Wert

1. Leg die Number in der YAML so an, dass das Gerät Werte von außen übernimmt. Bei `platform: template` heißt das `optimistic: true` oder eine eigene `set_action`.
2. Spiel die Firmware auf und warte, bis sich der Adapter neu verbunden hat.
3. Öffne im Admin den Tab „Objekte“ und dort `esphome.0.<Gerät>.Number.<Schlüssel>`.
4. Schreib einen Wert in `state`. Meldet das Gerät den neuen Wert, steht er bestätigt (`ack = true`) im Datenpunkt.
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; extern=esphome.io/components/number/template; forum=1007754 -->

```yaml
number:
  - platform: template
    name: "Zieltemperatur"
    optimistic: true
    min_value: 15
    max_value: 25
    step: 0.5
    unit_of_measurement: "°C"
```
<!-- quelle: extern=esphome.io/components/number/template -->

```javascript
setState('esphome.0.<Gerät>.Number.<Schlüssel>.state', 21.5);
```
<!-- quelle: code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

### Was der Adapter aus der YAML übernimmt

| Aus der YAML | Im Datenpunkt |
|---|---|
| `unit_of_measurement` | Einheit |
| `accuracy_decimals` | Der Wert wird darauf gerundet. |
| `min_value`, `max_value`, `step` | nicht im Datenpunkt, nur im Ordner `config`, wenn „Konfigurationszustände anzeigen“ an ist |
<!-- quelle: code=src/main.ts:573-579@v2.0.0-beta.2; code=src/main.ts:631-680@v2.0.0-beta.2; code=src/main.ts:952-981@v2.0.0-beta.2 -->

Den Bereich trägst du deshalb im VIS-Widget oder Alias selbst ein. Der Adapter prüft beim Schreiben keinen Bereich, Werte außerhalb behandelt die Firmware.
<!-- quelle: code=src/main.ts:952-981@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

Ein Template-`binary_sensor` ist nur lesbar. Willst du einen Ein/Aus-Wert an das Gerät schicken, nimm einen Template-`switch`.
<!-- quelle: code=src/main.ts:715-717@v2.0.0-beta.2 -->

Kennt der Adapter einen Entitätstyp nicht, legt er nur den Ordner an und schreibt einmal je Typ „DeviceType … not yet supported“ ins Log. Zu „deserializeBinary“ oder „Bad format“ siehe [Was die Meldung bedeutet](06.log-meldungen.md#deserializebinary-assertion-failed-bad-format).
<!-- quelle: code=src/main.ts:803-812@v2.0.0-beta.2 -->

## Wie ändere ich einen ESPHome-Select (Auswahlliste)?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=entities-scripts-20; features=entity-select -->
<!-- muss beantworten: Options erscheinen als Auswahlliste, Änderungen der Optionen erst nach Reconnect. -->

Ein Select erscheint als `esphome.0.<Gerät>.Select.<Schlüssel>.state`. Die Optionen aus der YAML hängen am Datenpunkt, der Tab „Objekte“ und VIS zeigen sie als Auswahlliste. Zum Ändern schreibst du den Text einer Option.
<!-- quelle: code=src/main.ts:970-973@v2.0.0-beta.2; code=src/main.ts:1819-1824@v2.0.0-beta.2; issue=#169 -->

```javascript
setState('esphome.0.<Gerät>.Select.<Schlüssel>.state', 'Eco');
```
<!-- quelle: code=src/main.ts:1819-1824@v2.0.0-beta.2 -->

Änderst du die Optionen in der YAML, übernimmt der Adapter sie bei der nächsten Verbindung nach dem Flashen. Lichteffekte sind keine Selects, sie stehen im Datenpunkt `effect` der Lampe.
<!-- quelle: code=src/main.ts:569-578@v2.0.0-beta.2; code=src/main.ts:1320-1340@v2.0.0-beta.2; issue=#146 -->
