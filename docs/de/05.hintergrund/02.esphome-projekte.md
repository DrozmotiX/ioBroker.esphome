# Wie passen bestehende ESPHome-Projekte zum Adapter?

<!-- seite: gewicht=8; en=en/05.hintergrund/02.esphome-projekte.md -->

<a id="custom-components-existing-esphome-projects"></a>

## Funktionieren eigene Komponenten und bestehende ESPHome-Projekte mit dem Adapter?

<!-- abschnitt: prio=B; gewicht=4; readme=partial; cluster=entities-scripts-27; features=entity-sensor,entity-textsensor,requirements-esphome-api -->
<!-- muss beantworten: Alles, was die native API als bekannte Entität liefert, erscheint; fremde Typen werden nur gewarnt. -->

Ja, solange die Firmware ihre Werte als Entitäten über die API meldet. Woher eine Entität kommt, ob aus ESPHome, einer externen Komponente oder einem fertigen Projekt, ist dem Adapter egal.
<!-- quelle: code=src/main.ts:569-627@v2.0.0-beta.2; forum=818941; forum=817053 -->

Der Adapter kennt diese Typen: Sensor, Binärsensor, Textsensor, Switch, Number, Text, Select, Button, Lock, Cover, Fan, Light und Climate. Meldet ein Gerät einen anderen Typ, steht einmal `DeviceType <Typ> not yet supported` mit den Details im Log, und für diesen Typ entstehen keine Werte. Für Typen wie Date, Time, Valve, Event oder Update steht stattdessen einmal `<Gerät> announced <Typ> "<Name>", the adapter does not support this entity type yet and skips it` im Log. Das Gerät bleibt verbunden, die übrigen Entitäten funktionieren.
<!-- quelle: code=src/main.ts:715-813@v2.0.0-beta.2; code=src/main.ts:1996-2009@v2.0.0-beta.2; code=src/lib/nativeApiMessages.ts; issue=#566 -->

Liefert eine Komponente einen JSON-Text, kommt er als ein Text-Datenpunkt an. Den zerlegst du im Skript mit `JSON.parse`. Vorhandene YAML-Dateien kannst du meist unverändert im Dashboard des Adapters nutzen.
<!-- quelle: code=src/main.ts:952-985@v2.0.0-beta.2; forum=1042377; forum=1315772 -->

<a id="use-esphome-over-mqtt-instead"></a>

## Kann ich ESPHome über MQTT statt oder zusätzlich zum Adapter nutzen?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=entities-scripts-28; features=requirements-esphome-api -->
<!-- muss beantworten: api und mqtt können parallel in der YAML stehen; Datentypen unterscheiden sich. -->

Beides geht. Der Adapter nutzt nur die Native API, `api:` und `mqtt:` dürfen zusammen in der YAML stehen. Die MQTT-Werte kommen dann zusätzlich über einen MQTT-Adapter, meist als Text wie `ON` und `OFF`.
<!-- quelle: code=src/main.ts:358-404@v2.0.0-beta.2; forum=526713; forum=553578 -->

Nutzt du nur MQTT, brauchst du diesen Adapter nicht. Lass dann `api:` aus der YAML weg. Mit `api:` startet ein Gerät nach 15 Minuten ohne API-Verbindung neu, wenn du `reboot_timeout` nicht auf `0s` setzt.
<!-- quelle: extern=esphome.io/components/api; forum=1139148 -->

<a id="manage-bluetooth-proxy-adapter-dashboard"></a>

## Kann ich einen Bluetooth-Proxy mit Adapter und Dashboard verwalten?

<!-- abschnitt: prio=B; gewicht=1; readme=partial; cluster=connection-setup-23; features=dashboard-enable,entity-unsupported,device-add-update-sendto -->
<!-- muss beantworten: Proxy-Funktion wird vom Adapter nicht ausgewertet, nur die normalen Entitäten; ein fertig geflashtes Gerät übernimmst du im Dashboard mit Adopt. -->

Einen Bluetooth-Proxy fügst du im Adapter wie jedes Gerät hinzu. Der Adapter zeigt seine normalen Entitäten, z. B. Sensoren und Buttons. Die Proxy-Funktion selbst nutzt er nicht, sie ist für Home Assistant gedacht.
<!-- quelle: code=src/main.ts:569-627@v2.0.0-beta.2; code=src/main.ts:715-813@v2.0.0-beta.2; forum=1322752 -->

Ein fertig geflashter Proxy erscheint im Dashboard des Adapters mit „Adopt“, wenn das Dashboard ihn im Netz findet. Damit legt das Dashboard eine YAML an, und du verwaltest und aktualisierst ihn dort.
<!-- quelle: code=README.md:117-131@v2.0.0-beta.2 -->
