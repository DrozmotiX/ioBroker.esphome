## How do I choose or update the ESPHome dashboard version, including older ones?

<!-- abschnitt: prio=A; gewicht=12; readme=missing; cluster=dashboard-05,logs-install-09; features=dashboard-version-select,dashboard-info-states,requirements-internet,dashboard-pillow-version,migration-pinned-versions,dashboard-clear-autopy-cache -->
<!-- muss beantworten: Version wählen oder eintippen, Device Builder und Pillow werden passend gewählt, Liste von GitHub, Always last available, Felder unter Fortschrittlich (Pillow, Device Builder, Python). -->

You select the version in the instance settings under "ESPHome Dashboard version" or type it there. After saving, the instance restarts and installs exactly this version. The default is `2026.6.5`.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=io-package.json:187@v2.0.0-beta.2; code=src/lib/dashboard.ts:497-501@v2.0.0-beta.2; issue=#118 -->

The adapter picks everything else ESPHome needs to match. From ESPHome 2026.7.0 on it also installs ESPHome Device Builder, which provides the dashboard there. ESPHome brings the matching Pillow version itself.
<!-- quelle: code=src/lib/dashboardRequirements.ts:66-68@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:88-107@v2.0.0-beta.2; issue=#479 -->

### How to do it

1. Open the instance settings, tab "ESPHome Dashboard".
2. Pick a version from the list under "ESPHome Dashboard version". If it is missing, for example an older one or a beta, type it in, e.g. `2026.5.3`.
3. Save. The instance restarts and installs the version. This takes a few minutes, meanwhile the ESPHome tab shows the start log.
4. The log then shows "Starting ESPHome Dashboard. ESPHome version: …" with the installed versions of ESPHome, Pillow and Device Builder.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=src/lib/dashboard.ts:573-576@v2.0.0-beta.2; code=src/lib/dashboard.ts:619-627@v2.0.0-beta.2; code=admin/jsonTab.json5:36-73@v2.0.0-beta.2 -->

<!-- bild: screenshot tab "ESPHome Dashboard" with the open list "ESPHome Dashboard version" -->

The list comes from GitHub when the instance starts and holds the 30 or so newest releases. If GitHub cannot be reached, the adapter uses the list from the last successful call. `esphome.0._ESPHomeDashboard.selectedVersion` shows the version in use, `esphome.0._ESPHomeDashboard.newestVersion` the newest one on GitHub.
<!-- quelle: code=src/lib/dashboard.ts:458-490@v2.0.0-beta.2; code=src/lib/dashboard.ts:1337-1351@v2.0.0-beta.2 -->

### What does "Always last available" mean?

With it, the adapter installs the newest ESPHome version at every start. If a release comes out that cannot be installed, the dashboard stops starting without any change on your side. Select a fixed version instead and change it deliberately to update.
<!-- quelle: code=src/lib/dashboard.ts:405-413@v2.0.0-beta.2; code=src/lib/dashboard.ts:497-506@v2.0.0-beta.2; issue=#463 -->

### What is under "Advanced"?

| Field | Default | Purpose |
|---|---|---|
| "Pillow version" | `Auto Detect` | ESPHome installs the matching version itself. Use a fixed version only if pip asks for exactly that one in the log. |
| "ESPHome Device Builder version" | `Auto Detect` | newest version that supports the selected ESPHome version |
| "Python version" | `3.13.2` | a version like `3.13.2` or a range like `3.12`. A change creates the Python environment again at the next start. |
<!-- quelle: code=admin/jsonConfig.json5:538-581@v2.0.0-beta.2; code=io-package.json:187-190@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:77-107@v2.0.0-beta.2 -->

With "Use Docker Integration (Beta)" these three fields are hidden. The adapter then starts the official ESPHome image in the selected version.
<!-- quelle: code=admin/jsonConfig.json5:538-581@v2.0.0-beta.2; code=src/lib/dashboard.ts:752-776@v2.0.0-beta.2 -->

If the dashboard itself reports an update, that only affects its own display. Which version runs is decided by the adapter setting alone.
<!-- quelle: code=src/lib/dashboard.ts:497-506@v2.0.0-beta.2; code=src/lib/dashboard.ts:580-586@v2.0.0-beta.2 -->

## How do I use an external ESPHome dashboard instead of the built-in one?

<!-- abschnitt: prio=B; gewicht=4; readme=covered; cluster=dashboard-14; features=dashboard-enable,dashboard-url-admin-tab,requirements-esphome-api -->
<!-- muss beantworten: Integriertes Dashboard abschalten und ESPHome anderswo betreiben; Adapter braucht nur Geräteadresse und Schlüssel; Docker-Integration als Alternative; was der Admin-Tab dann zeigt. -->

The integrated dashboard is optional. For the devices the adapter only needs their address and key. Where you edit the YAML files and flash does not matter to it.
<!-- quelle: code=README.md:83-91@v2.0.0-beta.2; forum=1349357; forum=607644 -->

1. Leave "Enable ESPHome Dashboard" off in the tab "ESPHome Dashboard".
2. Run ESPHome on another machine, e.g. as a Docker container or Home Assistant add-on.
3. Add the devices in the tab "Devices" with address and key.
<!-- quelle: code=admin/jsonConfig.json5:369-378@v2.0.0-beta.2; code=README.md:251-255@v2.0.0-beta.2 -->

While the integrated dashboard is off, the admin tab "ESPHome" only shows the hint that it is not enabled. Open the external dashboard directly in the browser at its address, e.g. `http://<host>:6052`.
<!-- quelle: code=admin/jsonTab.json5:21-26@v2.0.0-beta.2; code=admin/jsonTab.json5:77-83@v2.0.0-beta.2; code=src/lib/dashboard.ts:436-440@v2.0.0-beta.2 -->

If you want ESPHome in Docker without the effort, use "Use Docker Integration (Beta)". The adapter then starts the official ESPHome image itself. You only see the option in the expert mode of admin.
<!-- quelle: code=admin/jsonConfig.json5:381-392@v2.0.0-beta.2; code=README.md:220-246@v2.0.0-beta.2 -->
