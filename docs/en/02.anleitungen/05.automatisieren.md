## How do I show devices in VIS, set times and list all devices in a script?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-29; features=state-id-scheme,entity-switch -->
<!-- muss beantworten: Datenpunkt-Pfad aufbauen, per Selektor alle Geräte finden und Werte in VIS schreiben. -->

The adapter provides no ready-made interface, only states. Use them in VIS, scripts and schedules like any other state. A path looks like this: `esphome.0.<device>.<type>.<key>.state`.
<!-- quelle: code=src/main.ts:591-627@v2.0.0-beta.2; code=src/main.ts:952-985@v2.0.0-beta.2; forum=1245125; forum=1119031 -->

In a script you find all devices by their online state. The display name is in the device object:

```javascript
$('state[id=esphome.0.*.info._online]').each(id => {
    const device = id.split('.')[2];
    log(`${getObject(`esphome.0.${device}`).common.name}: ${getState(id).val}`);
});
```
<!-- quelle: code=src/main.ts:513-533@v2.0.0-beta.2; code=src/main.ts:2011-2039@v2.0.0-beta.2 -->

To switch on a schedule, let a schedule write the state:

```javascript
schedule('0 7 * * *', () => {
    setState('esphome.0.<device>.Switch.<key>.state', true);
});
```
<!-- quelle: code=src/main.ts:1770-1775@v2.0.0-beta.2; forum=1215708 -->

## How do I use ESPHome datapoints in aliases, Alexa or the IoT adapter?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-15; features=entity-number,state-roles-metadata -->
<!-- muss beantworten: Alias mit passenden Rollen; die Adapter-Rollen sind überwiegend generisch, Cover-Position ist schon 0 bis 100. -->

Most states of the adapter have the generic role `state`. Alexa and the IoT adapter therefore do not recognise them as a light, blind or thermostat. Create an alias, e.g. in the adapter "Devices", and link it to the ESPHome state.
<!-- quelle: code=src/main.ts:1310@v2.0.0-beta.2; code=src/lib/stateAttr.ts:18-97@v2.0.0-beta.2; forum=1352068; issue=#148 -->

Some states already have a fitting role:

| State | Role |
|---|---|
| Cover `position` (0 to 100 %) | `level.blind` |
| Cover `tilt` (0 to 100 %) | `level.tilt` |
| Button `SET`, Cover `stop` | `button` |
| Lock `state` / `command` | `sensor.lock` / `level.lock` |
| `info._online` | `indicator.reachable` |
<!-- quelle: code=src/lib/stateAttr.ts:18-65@v2.0.0-beta.2; code=src/lib/stateAttr.ts:144-150@v2.0.0-beta.2; code=src/main.ts:723-748@v2.0.0-beta.2 -->

If a number should appear as on/off in the alias, use a read and a write function in the alias, e.g. `val == 60` and `val ? 60 : -5`. The adapter takes the unit from `unit_of_measurement` in the YAML. If it is missing, Alexa may calculate wrongly; add it to the YAML then.
<!-- quelle: code=src/main.ts:576-578@v2.0.0-beta.2; forum=1352068; forum=1233149 -->

## How do I send text or values to an ESPHome display?

<!-- abschnitt: prio=A; gewicht=12; readme=missing; cluster=entities-scripts-16; features=entity-text,entity-number,entity-switch -->
<!-- muss beantworten: Text- und Number-Entitäten der YAML anlegen, Datenpunkt beschreiben, Display liest die Entität. -->

Define a text entity (`text:`) for texts and a number entity (`number:`) for numbers in the YAML and print them in the display lambda. In ioBroker you write `esphome.0.<device>.Text.<key>.state` or `esphome.0.<device>.Number.<key>.state`, the adapter sends the value to the device.
<!-- quelle: code=src/main.ts:768-775@v2.0.0-beta.2; code=src/main.ts:1799-1810@v2.0.0-beta.2; issue=#103; issue=#141 -->

Use a text entity for texts, not a text sensor (`text_sensor:`). Its state can be written, but the value does not reach the device.
<!-- quelle: code=src/main.ts:760-762@v2.0.0-beta.2; code=src/main.ts:1700-1860@v2.0.0-beta.2 -->

### How to do it

1. Add a text entity and, if needed, a number entity to the YAML, both with `optimistic: true` and an `id`.
2. Print the values in your display's `lambda`.
3. Flash the firmware and wait until the adapter has reconnected. The new entities appear under `esphome.0.<device>.Text` and `esphome.0.<device>.Number`.
4. Write your text to `Text.<key>.state` or your number to `Number.<key>.state`. The display shows the value at the next redraw.
<!-- quelle: code=src/main.ts:768-775@v2.0.0-beta.2; code=src/main.ts:1799-1810@v2.0.0-beta.2; extern=esphome.io/components/text/template; extern=esphome.io/components/number/template -->

```yaml
text:
  - platform: template
    name: "Display text"
    id: display_text
    optimistic: true
    mode: text
    max_length: 64

number:
  - platform: template
    name: "Display value"
    id: display_value
    optimistic: true
    min_value: -50
    max_value: 100
    step: 0.1

display:
  - platform: <your display platform>
    lambda: |-
      it.printf(0, 0, id(my_font), "%s", id(display_text).state.c_str());
      it.printf(0, 20, id(my_font), "%.1f", id(display_value).state);
```
<!-- quelle: extern=esphome.io/components/text/template; extern=esphome.io/components/number/template; extern=esphome.io/components/display -->

<!-- bild: object tree with Text.<key>.state and Number.<key>.state of a display device -->

To show a value from another adapter, e.g. a temperature, copy it into the ESPHome state with a script. The adapter does not check the length of a text, stick to `max_length` from the YAML.
<!-- quelle: code=src/main.ts:1806-1810@v2.0.0-beta.2; forum=632606 -->

```javascript
on({ id: '<adapter>.0.<sensor>.TEMPERATURE', change: 'ne' }, obj => {
    setState('esphome.0.<device>.Number.<key>.state', obj.state.val);
});
setState('esphome.0.<device>.Text.<key>.state', 'Bins: Tuesday');
```
<!-- quelle: code=src/main.ts:1799-1810@v2.0.0-beta.2; forum=632606 -->
