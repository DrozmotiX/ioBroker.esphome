## Which reconnect settings exist and what happens when a device goes offline?

<!-- abschnitt: prio=A; gewicht=9; readme=missing; cluster=connection-setup-08; features=connection-behavior-settings,device-startup-reconnect,info-device-online,info-connection-status,logging-connection-errors -->
<!-- muss beantworten: Reconnect-Intervall, Ping-Intervall, Ping-Versuche (Standard 30/5/1) im Reiter Haupteinstellungen, automatisches Wiederverbinden, info._online, info._connectionStatus, info.connectedDevices. -->

After every connection loss the adapter reconnects by itself, until the device answers again. How quickly it notices an outage and how often it retries is set in the "Main settings" tab under "Connection behavior for known devices". The values apply to all devices of the instance.
<!-- quelle: code=src/main.ts:366-390@v2.0.0-beta.2; code=admin/jsonConfig.json5:184-250@v2.0.0-beta.2 -->

| Field | What it does | Default | Allowed |
|---|---|---|---|
| "Reconnect interval (seconds)" | wait time before every new connection attempt | 30 | 1 to 3600 |
| "Ping interval (seconds)" | how often the adapter pings a connected device | 5 | 1 to 3600 |
| "Ping attempts before offline" | how many pings in a row may fail before the device counts as offline | 1 | 1 to 100 |
<!-- quelle: code=io-package.json:191-193@v2.0.0-beta.2; code=admin/jsonConfig.json5:205-250@v2.0.0-beta.2; interview=12 -->

The help text under "Reconnect interval" says 5 seconds. The adapter only uses this value when the field is empty. What is in the field applies.
<!-- quelle: code=admin/i18n/en.json:39@v2.0.0-beta.2; code=src/main.ts:371-373@v2.0.0-beta.2; interview=12 -->
<!-- issue: A1 -->

With a 5-second ping interval and 1 ping attempt, the adapter notices an outage after about 5 seconds. With 3 attempts it takes about 15 seconds, but a single lost ping on Wi-Fi does not drop the connection.
<!-- quelle: code=src/main.ts:371-387@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/connection.js:85-96@1.3.7 -->

### What happens when a device goes offline

1. The adapter notices the drop, because the connection breaks or the configured pings fail.
2. `esphome.0.<device>.info._online` becomes `false`, `info._connectionStatus` names the reason.
3. After the "Reconnect interval" the adapter connects again, without limit.
4. When the device answers again, it reads device information and entities again. The log shows "ESPHome client <IP> connected".
<!-- quelle: code=src/main.ts:398-472@v2.0.0-beta.2; code=src/main.ts:854-935@v2.0.0-beta.2; code=src/main.ts:2134-2170@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/connection.js:45-56@1.3.7 -->

You do not need to restart the adapter for this.
<!-- quelle: code=src/main.ts:398-402@v2.0.0-beta.2 -->

### The status display

`info._online` is `true` while the device is connected and has the role `indicator.reachable`. The "Devices" tab shows the same status. `esphome.0.info.connectedDevices` lists the names of all connected devices, `esphome.0.info.connection` is `true` while the instance runs.
<!-- quelle: code=src/lib/stateAttr.ts:142-150@v2.0.0-beta.2; code=src/lib/connectionState.ts:13-75@v2.0.0-beta.2; code=src/main.ts:2177-2212@v2.0.0-beta.2; issue=#562 -->

`info._connectionStatus` names the state as text:

| Value | Meaning |
|---|---|
| `connecting`, `initializing`, `Initializing` | Connecting or reading the device. |
| `Connected`, `connected`, `initialized` | Connected, values are arriving. |
| `disconnected` | Disconnected, the next attempt follows after the "Reconnect interval". |
| `connection lost` | Connection broke (`ECONNRESET`). |
| `unreachable` | The device does not answer. |
| `No Network` | The network of the ioBroker host is not ready yet. |
| `API password incorrect` | The API password is wrong. |
| `Encryption Key Missing` | The device requires an encryption key, the adapter has none. |
| `error` | Another error, the message is in the log. |
<!-- quelle: code=src/main.ts:366@v2.0.0-beta.2; code=src/main.ts:407@v2.0.0-beta.2; code=src/main.ts:427@v2.0.0-beta.2; code=src/main.ts:472@v2.0.0-beta.2; code=src/main.ts:556@v2.0.0-beta.2; code=src/main.ts:706@v2.0.0-beta.2; code=src/main.ts:854-935@v2.0.0-beta.2 -->

Waiting does not help with `API password incorrect` and `Encryption Key Missing`. Enter the correct credentials in the "Devices" tab under "Change connection settings".
<!-- quelle: code=src/main.ts:872-886@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:270-278@v2.0.0-beta.2; issue=#203 -->

### When a device stays offline

1. Read what the log reports for the device. The meaning is under [Log messages](06.log-meldungen.md#log-full-errors-connections-drop).
2. Check that the device can be reached on the network, e.g. through its web page if it uses `web_server:`.
3. Restart the device. If it does not come back by itself, restart the instance.

## What does the option "Show configuration states" do, and what are the info and config folders?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-03,logs-install-24; features=info-device-information,config-states-setting,traverse-json-states -->
<!-- muss beantworten: Die Option legt je Entität einen config-Ordner (nur lesbar) an; Verschachteltes erscheint als JSON-Text; info enthält die Geräteinformationen, _online und _connectionStatus. -->

Every device has two folders with additional information.

The adapter always creates **`info`** once the device is connected. It holds what the device reports about itself, e.g. name, MAC address, ESPHome version, compile time and model, plus `_online` and `_connectionStatus`.
<!-- quelle: code=src/main.ts:536-559@v2.0.0-beta.2; code=src/main.ts:1194-1270@v2.0.0-beta.2; code=src/main.ts:2134-2180@v2.0.0-beta.2; forum=686829 -->

**`config`** exists under every entity when "Show configuration states" is on. The option is in the tab "Main settings" and is off by default. The folder shows the configuration of the entity from the API, e.g. name, unit, device class and decimals. The values are read-only, nested data is stored as JSON text in one state.
<!-- quelle: code=admin/jsonConfig.json5:192-202@v2.0.0-beta.2; code=io-package.json:196@v2.0.0-beta.2; code=src/main.ts:632-681@v2.0.0-beta.2; code=src/main.ts:1194-1270@v2.0.0-beta.2; forum=672010 -->

If the option is off, the adapter deletes existing `config` folders on the next connection. You do not need them for control. The only exception is `config.rgbAutoWhite` of RGBW lights.
<!-- quelle: code=src/main.ts:632-646@v2.0.0-beta.2; code=src/main.ts:1117-1146@v2.0.0-beta.2; forum=833760 -->
