## How do I see and write an ESPHome Number (template slider)?

<!-- abschnitt: prio=A; gewicht=13; readme=missing; cluster=entities-scripts-14,entities-scripts-13; features=entity-number,entity-binarysensor,entity-button,entity-unsupported -->
<!-- muss beantworten: Number ist beschreibbar; Min/Max/Step stehen nur im config-Ordner; Template-Binärsensor ist nur lesbar; unbekannte Typen. -->

A number from the YAML, e.g. a template slider, appears as the writable state `esphome.0.<device>.Number.<key>.state`. When you write a number there, the adapter sends it straight to the device through the Native API.
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; forum=1007754 -->

### How to write a number value

1. Define the number in the YAML so that the device accepts values from outside. For `platform: template` this means `optimistic: true` or your own `set_action`.
2. Flash the firmware and wait until the adapter has reconnected.
3. In admin, open the "Objects" tab and go to `esphome.0.<device>.Number.<key>`.
4. Write a value to `state`. When the device reports the new value, it is confirmed (`ack = true`).
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; extern=esphome.io/components/number/template; forum=1007754 -->

```yaml
number:
  - platform: template
    name: "Target temperature"
    optimistic: true
    min_value: 15
    max_value: 25
    step: 0.5
    unit_of_measurement: "°C"
```
<!-- quelle: extern=esphome.io/components/number/template -->

```javascript
setState('esphome.0.<device>.Number.<key>.state', 21.5);
```
<!-- quelle: code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

### What the adapter takes over from the YAML

| From the YAML | In the state |
|---|---|
| `unit_of_measurement` | unit |
| `accuracy_decimals` | The value is rounded to it. |
| `min_value`, `max_value`, `step` | not in the state, only in the `config` folder when "Show configuration states" is on |
<!-- quelle: code=src/main.ts:573-579@v2.0.0-beta.2; code=src/main.ts:631-680@v2.0.0-beta.2; code=src/main.ts:952-981@v2.0.0-beta.2 -->

Enter the range in the VIS widget or alias yourself. The adapter does not check a range when writing, values outside are handled by the firmware.
<!-- quelle: code=src/main.ts:952-981@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

A template `binary_sensor` is read-only. To send an on/off value to the device, use a template `switch`.
<!-- quelle: code=src/main.ts:715-717@v2.0.0-beta.2 -->

If the adapter does not know an entity type, it only creates the folder and logs "DeviceType … not yet supported" once per type. For "deserializeBinary" or "Bad format" see [What the message means](06.log-meldungen.md#deserializebinary-assertion-failed-bad-format).
<!-- quelle: code=src/main.ts:803-812@v2.0.0-beta.2 -->
