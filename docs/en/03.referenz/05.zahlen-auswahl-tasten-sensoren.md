## How do I see and write an ESPHome Number (template slider)?

<!-- abschnitt: prio=A; gewicht=13; readme=missing; cluster=entities-scripts-14,entities-scripts-13; features=entity-number,entity-binarysensor,entity-button,entity-unsupported -->
<!-- muss beantworten: Number ist beschreibbar; Min/Max/Step stehen nur im config-Ordner; Template-Binärsensor ist nur lesbar; unbekannte Typen. -->

A number from the YAML, e.g. a template slider, appears as the writable state `esphome.0.<device>.Number.<key>.state`. When you write a number there, the adapter sends it straight to the device through the Native API.
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; forum=1007754 -->

### How to write a number value

1. Define the number in the YAML so that the device accepts values from outside. For `platform: template` this means `optimistic: true` or your own `set_action`.
2. Flash the firmware and wait until the adapter has reconnected.
3. In admin, open the "Objects" tab and go to `esphome.0.<device>.Number.<key>`.
4. Write a value to `state`. When the device reports the new value, it is confirmed (`ack = true`).
<!-- quelle: code=src/main.ts:768-770@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2; extern=esphome.io/components/number/template; forum=1007754 -->

```yaml
number:
  - platform: template
    name: "Target temperature"
    optimistic: true
    min_value: 15
    max_value: 25
    step: 0.5
    unit_of_measurement: "°C"
```
<!-- quelle: extern=esphome.io/components/number/template -->

```javascript
setState('esphome.0.<device>.Number.<key>.state', 21.5);
```
<!-- quelle: code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

### What the adapter takes over from the YAML

| From the YAML | In the state |
|---|---|
| `unit_of_measurement` | unit |
| `accuracy_decimals` | The value is rounded to it. |
| `min_value`, `max_value`, `step` | not in the state, only in the `config` folder when "Show configuration states" is on |
<!-- quelle: code=src/main.ts:573-579@v2.0.0-beta.2; code=src/main.ts:631-680@v2.0.0-beta.2; code=src/main.ts:952-981@v2.0.0-beta.2 -->

Enter the range in the VIS widget or alias yourself. The adapter does not check a range when writing, values outside are handled by the firmware.
<!-- quelle: code=src/main.ts:952-981@v2.0.0-beta.2; code=src/main.ts:1799-1803@v2.0.0-beta.2 -->

A template `binary_sensor` is read-only. To send an on/off value to the device, use a template `switch`.
<!-- quelle: code=src/main.ts:715-717@v2.0.0-beta.2 -->

If the adapter does not know an entity type, it only creates the folder and logs "DeviceType … not yet supported" once per type. For "deserializeBinary" or "Bad format" see [What the message means](06.log-meldungen.md#deserializebinary-assertion-failed-bad-format).
<!-- quelle: code=src/main.ts:803-812@v2.0.0-beta.2 -->

## How do I change an ESPHome Select (dropdown)?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=entities-scripts-20; features=entity-select -->
<!-- muss beantworten: Options erscheinen als Auswahlliste, Änderungen der Optionen erst nach Reconnect. -->

A select appears as `esphome.0.<device>.Select.<key>.state`. The options from the YAML are attached to the state, the tab "Objects" and VIS show them as a drop-down list. To change it, write the text of an option.
<!-- quelle: code=src/main.ts:970-973@v2.0.0-beta.2; code=src/main.ts:1819-1824@v2.0.0-beta.2; issue=#169 -->

```javascript
setState('esphome.0.<device>.Select.<key>.state', 'Eco');
```
<!-- quelle: code=src/main.ts:1819-1824@v2.0.0-beta.2 -->

If you change the options in the YAML, the adapter takes them over on the next connection after flashing. Light effects are not selects, they are in the state `effect` of the light.
<!-- quelle: code=src/main.ts:569-578@v2.0.0-beta.2; code=src/main.ts:1320-1340@v2.0.0-beta.2; issue=#146 -->

## How do I trigger a button, restart or script of a device?

<!-- abschnitt: prio=B; gewicht=6; readme=missing; cluster=entities-scripts-19; features=entity-button,entity-switch -->
<!-- muss beantworten: Jeder Schreibzugriff mit ack=false löst den Button aus, der Wert wird nicht zurückgesetzt. -->

A button appears as `esphome.0.<device>.Button.<key>.SET`. Every write with `ack = false` presses it, whatever the value. The adapter does not reset the value afterwards.
<!-- quelle: code=src/main.ts:1996-2009@v2.0.0-beta.2; code=src/main.ts:1813-1817@v2.0.0-beta.2; code=src/lib/stateAttr.ts:43-50@v2.0.0-beta.2; issue=#127 -->

Turn a restart, scripts and other actions into a button in the YAML:

```yaml
button:
  - platform: restart
    name: "Restart"
  - platform: template
    name: "Run script"
    on_press:
      - script.execute: my_script
```
<!-- quelle: extern=esphome.io/components/button; forum=781590; forum=765189 -->

**See also:** [When a command is acknowledged](02.datenpunkte.md#command-acknowledged-ack-happens-offline)

## Why does my binary sensor show no value or only a folder?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-25; features=entity-binarysensor,entity-sensor -->
<!-- muss beantworten: Binary-Sensor-Zustand liegt im Unterdatenpunkt state, Rolle generisch. -->

The value of a binary sensor is in the state `esphome.0.<device>.BinarySensor.<key>.state`, `true` or `false`, read-only. The folder above it is the entity itself.
<!-- quelle: code=src/main.ts:609-627@v2.0.0-beta.2; code=src/main.ts:715-717@v2.0.0-beta.2; issue=#142 -->

The adapter only creates the state `state` once the device reports its first value. If you only see the folder, the device has sent no value since the connection. Check in the device log whether the sensor has a value.
<!-- quelle: code=src/main.ts:704-717@v2.0.0-beta.2; forum=856155 -->

Presence sensors often report motion, presence and similar as separate binary sensors. Query the right one in your script, its name is in the column "Name".
<!-- quelle: forum=1326786 -->
