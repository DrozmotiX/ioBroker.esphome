## Why is the log full of errors when connections drop and reconnect?

<!-- abschnitt: prio=B; gewicht=8; readme=missing; cluster=logs-install-10,logs-install-11,connection-setup-12; features=logging-connection-errors,logging-connection-lifecycle,connection-behavior-settings,device-delete-sendto -->
<!-- muss beantworten: Welche Meldungen bei Offline-Geräten normal sind ("not ready to connect yet" bei jedem Versuch), was der Adapter nur einmal meldet, Log-Level. -->

If a device is offline, the adapter tries again at every reconnect interval. It reports most errors once per outage, some on every attempt:

| Message | how often |
|---|---|
| `Device <IP> is unreachable`, `… requires an encryption key …` | once per outage |
| `Connection to device <IP> lost …`, `Timeout connecting …`, `Network not ready …` | once per outage |
| `ESPHome client … disconnected` | on every disconnect |
| `Device <IP> is not ready to connect yet, the adapter tries again` | on every attempt |
| `Device <IP> rejected the API password` | on every attempt |
| `ESPHome client <IP> <error>` | on every attempt |
<!-- quelle: code=src/main.ts:854-918@v2.0.0-beta.2; code=src/main.ts:424-459@v2.0.0-beta.2; forum=885876; forum=599748; issue=#48 -->

This makes the log quieter:

1. Fix the cause, e.g. switch the device on or correct the credentials.
2. If you no longer need the device, delete it in the tab "Devices".
3. If it is often off for a long time, raise "Reconnect interval (seconds)" in the main settings.
<!-- quelle: code=admin/jsonConfig.json5:205-218@v2.0.0-beta.2; code=src/main.ts:368-372@v2.0.0-beta.2; forum=1079240; forum=675974 -->

You cannot pause single devices.

## What do "deserializeBinary", "Assertion failed", "Bad format" and "Invalid wire type" mean?

<!-- abschnitt: prio=A; gewicht=19; readme=missing; cluster=connection-setup-05,logs-install-23,connection-setup-04; features=logging-connection-errors,logging-connection-lifecycle,device-credentials-storage,requirements-esphome-api -->
<!-- muss beantworten: Meldungen der native-api-Bibliothek bei Verschlüsselungs- oder Versionskonflikt; Schlüssel im Reiter Geräte prüfen, Gerät neu hinzufügen. -->

These messages come from the library the adapter uses to talk to the device (`@2colors/esphome-native-api`). They mean that adapter and device do not match, usually in the encryption key, less often because the firmware sends messages the library does not know.
<!-- quelle: code=src/main.ts:854-918@v2.0.0-beta.2; code=package.json:33@v2.0.0-beta.2; interview=15; issue=#200 -->

The adapter turns a missing key, a wrong API password and network errors into its own messages. All other errors appear unchanged as `ESPHome client <IP> <error>` in the log, again with every connection attempt.
<!-- quelle: code=src/main.ts:860-916@v2.0.0-beta.2 -->
<!-- issue: A4 -->

| Log message | What is behind it | What to do |
|---|---|---|
| `Device <IP> requires an encryption key` | The device uses encryption, the adapter has no key. | Enter the key from `api:` → `encryption:` → `key:` for the device. |
| `Bad format. Expected 1 at the begin` | The adapter has a key, but the device answers unencrypted. | Turn on encryption in the YAML and flash again, or remove the key in the adapter. |
| `Bad format. Expected 0 at the begin` | Something other than the ESPHome API answers at the address. | Check that the device really runs at this address. |
| `Handshake failure` | The device rejected the key. | Compare the key in YAML and adapter character by character. |
| `Failed find or parsed message type for Id: <number>` | The library could not read a message from the device and drops the connection. | Steps below. |
| `deserializeBinary`, `Assertion failed`, `Invalid wire type` | Same cause as the line above. | Steps below. |
<!-- quelle: code=src/main.ts:878-886@v2.0.0-beta.2; code=src/i18n/en.json:17@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/utils/plaintextFrameHelper.js:32-33@1.3.7; code=node_modules/@2colors/esphome-native-api/lib/utils/noiseFrameHelper.js:63@1.3.7; code=node_modules/@2colors/esphome-native-api/lib/utils/noiseFrameHelper.js:121@1.3.7; code=node_modules/@2colors/esphome-native-api/lib/utils/frameHelper.js:55-65@1.3.7; forum=758017; forum=810128; forum=759216; issue=#200; issue=#152; interview=15 -->

### How to do it

1. Check that the device's YAML has an `api:` section. Without it the adapter cannot talk to the device.
2. Compare the key under `api:` → `encryption:` → `key:` with the one in the adapter. To do so, open "Change connection settings" for the device in the "Devices" tab. If the device has no encryption, the field must be empty.
3. If you just moved the firmware to a new ESPHome version, the library may not know its messages yet. Then a newer adapter version helps, or the older firmware for now.
4. If the message keeps coming, delete the device in the "Devices" tab and add it again with address and key.
5. It worked when the log shows `ESPHome client <IP> connected` and `esphome.0.<device>.info._online` turns `true`.
<!-- quelle: interview=15; interview=2; code=src/lib/deviceManagement.ts:270-288@v2.0.0-beta.2; code=src/main.ts:405-410@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/utils/frameHelper.js:55-65@1.3.7; issue=#200; forum=758017 -->

A device that answers a ping can still be offline for the adapter. A ping only checks the network, these messages concern the ESPHome API on port 6053.
<!-- quelle: forum=810128; interview=14 -->

## Why do I constantly see adapter connections in the device log?

<!-- abschnitt: prio=B; gewicht=4; readme=missing; cluster=logs-install-08; features=connection-behavior-settings,logging-connection-lifecycle -->
<!-- muss beantworten: Der Adapter hält pro Gerät eine API-Verbindung; Reconnects und Pings erscheinen im ESP-Log. -->

The adapter keeps a permanent connection to every device over the ESPHome API. In the device log it shows up with the name of the ioBroker host. It checks the connection at the ping interval and re-establishes it after a drop at the reconnect interval.
<!-- quelle: code=src/main.ts:368-390@v2.0.0-beta.2; forum=1091770 -->

One connection per adapter restart is normal. If you constantly see new connections, the connection keeps dropping. Check the Wi-Fi of the device then and raise the ping attempts under "Connection behavior for known devices".
<!-- quelle: code=admin/jsonConfig.json5:184-250@v2.0.0-beta.2; forum=1136379; forum=1327547 -->

The adapter writes the messages of the device itself into its log only at log level "debug".
<!-- quelle: code=src/main.ts:483-490@v2.0.0-beta.2 -->
