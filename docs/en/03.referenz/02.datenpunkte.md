## Why does the datapoint path contain a number instead of the sensor name?

<!-- abschnitt: prio=B; gewicht=7; readme=missing; cluster=entities-scripts-01; features=state-id-scheme -->
<!-- muss beantworten: Pfad-Schema Gerät.Typ.Schlüssel.Zustand, Zahl ist der ESPHome-Entity-Key, lesbarer Name steht im Channel-Namen; nicht änderbar. -->

The number is the key ESPHome gives the entity. The adapter builds every path like this:

`esphome.0.<device>.<type>.<key>.<state>`, e.g. `esphome.0.A1B2C3D4E5F6.Sensor.1234567890.state`
<!-- quelle: code=src/main.ts:591-627@v2.0.0-beta.2; code=src/main.ts:952-985@v2.0.0-beta.2; forum=686417; issue=#49 -->

| Part | Content |
|---|---|
| `<device>` | MAC address without colons |
| `<type>` | kind of entity, e.g. `Sensor`, `Switch`, `Light` |
| `<key>` | key of the entity from the API |
| `<state>` | usually `state`, several for lights, covers and fans |
<!-- quelle: code=src/main.ts:497-501@v2.0.0-beta.2; code=src/main.ts:591-627@v2.0.0-beta.2 -->

The tab "Objects" shows the readable name from the YAML in the column "Name" of the entity folder. The adapter cannot change the path. If you rename the entity in the YAML, ESPHome changes the key and the path becomes a new one. The adapter removes the old folder after the connection.
<!-- quelle: code=src/main.ts:609-617@v2.0.0-beta.2; code=src/main.ts:2041-2090@v2.0.0-beta.2; forum=613419; issue=#222; issue=#449 -->

If you want fixed, readable names, create an alias.

**See also:** [Create aliases](../02.anleitungen/05.automatisieren.md#use-esphome-datapoints-aliases-alexa) · [Clean up old states](../02.anleitungen/02.geraete-verwalten.md#clean-up-devices-datapoints-no)

## Where do I find online status, WiFi signal, IP and uptime of a device?

<!-- abschnitt: prio=B; gewicht=5; readme=missing; cluster=entities-scripts-02,connection-setup-11,entities-scripts-31; features=entity-sensor,entity-textsensor,info-device-information,info-device-online,info-connection-status,info-connection -->
<!-- muss beantworten: info._online pro Gerät (indicator.reachable), info._connectionStatus, info.connection zeigt nur, ob die Instanz läuft, info.connectedDevices listet verbundene Geräte; WLAN-Signal auch im Reiter Geräte. -->

Whether a device is connected is shown by `esphome.0.<device>.info._online`: `true` while the connection stands, otherwise `false`. The state has the role `indicator.reachable`. The exact status, e.g. `unreachable` or `Encryption Key Missing`, is in `info._connectionStatus`.
<!-- quelle: code=src/main.ts:2134-2180@v2.0.0-beta.2; code=src/lib/stateAttr.ts:142-150@v2.0.0-beta.2; code=src/lib/connectionState.ts:40-42@v2.0.0-beta.2; issue=#106; issue=#311 -->

For the whole instance there are two states:

| State | Content |
|---|---|
| `esphome.0.info.connection` | `true` while the adapter runs |
| `esphome.0.info.connectedDevices` | names of the connected devices, comma-separated. With the dashboard enabled, the list stays empty until the dashboard answers. |
<!-- quelle: code=src/main.ts:2182-2223@v2.0.0-beta.2; code=src/lib/connectionState.ts:16-77@v2.0.0-beta.2 -->

ESPHome only reports Wi-Fi signal, IP address and uptime if they are sensors in the YAML, e.g. `wifi_signal`, `uptime` and `wifi_info`. They then appear under `Sensor` or `TextSensor` of the device. A `wifi_signal` sensor also shows the signal on the device card in the tab "Devices".
