## How do I control covers (including time_based): position, tilt, stop?

<!-- abschnitt: prio=A; gewicht=9; readme=missing; cluster=entities-scripts-11,entities-scripts-12; features=entity-cover -->
<!-- muss beantworten: Position und Neigung in Prozent lesen und schreiben, Stopp, time_based ohne Positionsrückmeldung zeigt 0. -->

A cover has the states `position`, `tilt` and `stop` under `esphome.0.<device>.Cover.<key>`. You read and write position and tilt in percent: `0` = closed, `100` = open.
<!-- quelle: code=src/main.ts:723-745@v2.0.0-beta.2; code=src/main.ts:1832-1856@v2.0.0-beta.2; issue=#549 -->

| State | Values | Role |
|---|---|---|
| `position` | 0 to 100 % | `level.blind` |
| `tilt` | 0 to 100 % | `level.tilt` |
| `stop` | any written value stops the cover | `button` |
<!-- quelle: code=src/main.ts:723-745@v2.0.0-beta.2; code=src/main.ts:1832-1856@v2.0.0-beta.2; code=src/lib/stateAttr.ts:18-40@v2.0.0-beta.2 -->

There is no separate state for open or close, you write `100` or `0` to `position`. If your cover has no tilt, ignore `tilt`. VIS sliders and voice assistants for the role `level.blind` work without conversion.
<!-- quelle: code=src/main.ts:1832-1849@v2.0.0-beta.2; code=src/lib/stateAttr.ts:18-24@v2.0.0-beta.2 -->

### How to move a blind to a position

1. In admin, open the "Objects" tab and go to `esphome.0.<device>.Cover.<key>`.
2. Write the target value to `position`, e.g. `30` for 30 % open.
3. The device starts moving and reports its position back. The state then shows it confirmed (`ack = true`).
4. To stop, write `true` to `stop`.
<!-- quelle: code=src/main.ts:723-745@v2.0.0-beta.2; code=src/main.ts:1832-1856@v2.0.0-beta.2 -->

```javascript
setState('esphome.0.<device>.Cover.<key>.position', 50);
setState('esphome.0.<device>.Cover.<key>.stop', true);
```
<!-- quelle: code=src/main.ts:1832-1856@v2.0.0-beta.2 -->

If `position` always stays at 0, the device reports no position through the API. For `time_based` covers this depends on the YAML, the adapter only shows what arrives.
<!-- quelle: code=src/main.ts:723-731@v2.0.0-beta.2; forum=608468 -->

## How do I control an ESPHome fan (speed, direction, oscillation)?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=entities-scripts-10; features=entity-fan -->
<!-- muss beantworten: Datenpunkte state, speed, speedLevel, direction (0 vorwärts, 1 rückwärts), oscillating; nur unterstützte sind beschreibbar. -->

A fan has these states under `esphome.0.<device>.Fan.<key>`:

| State | Values | writable |
|---|---|---|
| `state` | `true` / `false` | yes |
| `speedLevel` | 1 to the number of levels | only with `speed_count` in the YAML |
| `direction` | `0` forward, `1` reverse | only if the fan supports direction |
| `oscillating` | `true` / `false` | only if the fan can oscillate |
| `speed` | old speed value | no |
<!-- quelle: code=src/main.ts:1014-1050@v2.0.0-beta.2; code=src/lib/stateAttr.ts:68-97@v2.0.0-beta.2; issue=#11; issue=#205 -->

For the speed, write `speedLevel`. On every change the adapter sends all current values of the fan to the device together.
<!-- quelle: code=src/main.ts:1777-1790@v2.0.0-beta.2; forum=1265138 -->

## How do I operate an ESPHome lock?

<!-- abschnitt: prio=B; gewicht=1; readme=missing; cluster=entities-scripts-21; features=entity-lock -->
<!-- muss beantworten: Zustands- und Befehlsdatenpunkt mit Zahlenwerten; Befehl wird ohne Startwert angelegt. -->

A lock has two states under `esphome.0.<device>.Lock.<key>`.

| State | Values |
|---|---|
| `state` (read-only) | `0` unknown, `1` locked, `2` unlocked, `3` jammed, `4` locking, `5` unlocking |
| `command` | `0` unlock, `1` lock, `2` open |
<!-- quelle: code=src/main.ts:782-801@v2.0.0-beta.2; code=src/lib/stateAttr.ts:52-66@v2.0.0-beta.2; issue=#353 -->

To operate it, write `command`. The state has no initial value, so nothing triggers by itself after a restart. `state` shows whether it worked.
<!-- quelle: code=src/main.ts:789-799@v2.0.0-beta.2; code=src/main.ts:1826-1831@v2.0.0-beta.2 -->

## How do I control a climate device (for example a Midea conversion)?

<!-- abschnitt: prio=B; gewicht=1; readme=partial; cluster=entities-scripts-24; features=entity-climate,requirements-esphome-api,device-add-update-sendto -->
<!-- muss beantworten: Datenpunkte kommen aus dem Climate-Zustand der API, Temperaturen in Grad Celsius. -->

A climate device works if it runs ESPHome with a `climate:` entity, e.g. the component `midea`, and the YAML contains `api:`. Then add it like any device with address and key. Without ESPHome firmware it does not work.
<!-- quelle: code=src/main.ts:719-721@v2.0.0-beta.2; extern=esphome.io/components/climate/midea; forum=1346748 -->

The states under `esphome.0.<device>.Climate.<key>` match the values the device reports, e.g. `mode`, `targetTemperature` and `fanMode`. All are writable except `currentTemperature`. Temperatures are in °C.
<!-- quelle: code=src/main.ts:994-1056@v2.0.0-beta.2 -->

When you write a value, the adapter sends all current values of the device together. `mode` is a number from the ESPHome API, e.g. `0` off, `2` cool, `3` heat.
<!-- quelle: code=src/main.ts:1792-1797@v2.0.0-beta.2; extern=esphome.io/components/climate -->
