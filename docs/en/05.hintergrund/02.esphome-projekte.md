## Do custom components and existing ESPHome projects work with the adapter?

<!-- abschnitt: prio=B; gewicht=4; readme=partial; cluster=entities-scripts-27; features=entity-sensor,entity-textsensor,requirements-esphome-api -->
<!-- muss beantworten: Alles, was die native API als bekannte Entität liefert, erscheint; fremde Typen werden nur gewarnt. -->

Yes, as long as the firmware reports its values as entities over the API. Where an entity comes from, ESPHome itself, an external component or a ready-made project, does not matter to the adapter.
<!-- quelle: code=src/main.ts:569-627@v2.0.0-beta.2; forum=818941; forum=817053 -->

The adapter knows these types: sensor, binary sensor, text sensor, switch, number, text, select, button, lock, cover, fan, light and climate. If a device reports another type, the log shows `DeviceType <type> not yet supported` with the details once, and this type gets no values.
<!-- quelle: code=src/main.ts:715-813@v2.0.0-beta.2; code=src/main.ts:1996-2009@v2.0.0-beta.2 -->

If a component delivers a JSON text, it arrives as one text state. Split it in a script with `JSON.parse`. Existing YAML files usually work unchanged in the dashboard of the adapter.
<!-- quelle: code=src/main.ts:952-985@v2.0.0-beta.2; forum=1042377; forum=1315772 -->
