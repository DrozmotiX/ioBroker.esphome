# How do existing ESPHome projects fit the adapter?

<!-- seite: gewicht=8; de=de/05.hintergrund/02.esphome-projekte.md -->

<a id="custom-components-existing-esphome-projects"></a>

## Do custom components and existing ESPHome projects work with the adapter?

<!-- abschnitt: prio=B; gewicht=4; readme=partial; cluster=entities-scripts-27; features=entity-sensor,entity-textsensor,requirements-esphome-api -->
<!-- muss beantworten: Alles, was die native API als bekannte Entität liefert, erscheint; fremde Typen werden nur gewarnt. -->

Yes, as long as the firmware reports its values as entities over the API. Where an entity comes from, ESPHome itself, an external component or a ready-made project, does not matter to the adapter.
<!-- quelle: code=src/main.ts:569-627@v2.0.0-beta.2; forum=818941; forum=817053 -->

The adapter knows these types: sensor, binary sensor, text sensor, switch, number, text, select, button, lock, cover, fan, light and climate. If a device reports another type, the log shows `DeviceType <type> not yet supported` with the details once, and this type gets no values.
<!-- quelle: code=src/main.ts:715-813@v2.0.0-beta.2; code=src/main.ts:1996-2009@v2.0.0-beta.2 -->

If a component delivers a JSON text, it arrives as one text state. Split it in a script with `JSON.parse`. Existing YAML files usually work unchanged in the dashboard of the adapter.
<!-- quelle: code=src/main.ts:952-985@v2.0.0-beta.2; forum=1042377; forum=1315772 -->

<a id="use-esphome-over-mqtt-instead"></a>

## Can I use ESPHome over MQTT instead of or alongside the adapter?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=entities-scripts-28; features=requirements-esphome-api -->
<!-- muss beantworten: api und mqtt können parallel in der YAML stehen; Datentypen unterscheiden sich. -->

Both work. The adapter only uses the Native API, `api:` and `mqtt:` may be in the YAML together. The MQTT values then come in additionally via an MQTT adapter, usually as text such as `ON` and `OFF`.
<!-- quelle: code=src/main.ts:358-404@v2.0.0-beta.2; forum=526713; forum=553578 -->

If you only use MQTT, you do not need this adapter. Then leave `api:` out of the YAML. With `api:` a device restarts after 15 minutes without an API connection unless you set `reboot_timeout` to `0s`.
<!-- quelle: extern=esphome.io/components/api; forum=1139148 -->

## Can I manage a Bluetooth proxy with the adapter and dashboard?

<!-- abschnitt: prio=B; gewicht=1; readme=partial; cluster=connection-setup-23; features=dashboard-enable,entity-unsupported,device-add-update-sendto -->
<!-- muss beantworten: Proxy-Funktion wird vom Adapter nicht ausgewertet, nur die normalen Entitäten; ein fertig geflashtes Gerät übernimmst du im Dashboard mit Adopt. -->

You add a Bluetooth proxy to the adapter like any device. The adapter shows its normal entities, e.g. sensors and buttons. It does not use the proxy function itself, which is meant for Home Assistant.
<!-- quelle: code=src/main.ts:569-627@v2.0.0-beta.2; code=src/main.ts:715-813@v2.0.0-beta.2; forum=1322752 -->

A pre-flashed proxy appears in the dashboard of the adapter with "Adopt" if the dashboard finds it on the network. The dashboard then creates a YAML, and you manage and update it there.
<!-- quelle: code=README.md:117-131@v2.0.0-beta.2 -->
