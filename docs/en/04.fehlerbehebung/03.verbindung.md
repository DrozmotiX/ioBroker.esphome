# Why does my device not connect or keep dropping?

<a id="devices-offline-reporting-incorrect-password"></a>

## Why are all devices offline or reporting "incorrect password" after a restart or update?

<!-- abschnitt: prio=B; gewicht=6; readme=missing; cluster=connection-setup-07; features=device-startup-reconnect,device-credentials-storage,info-device-online -->
<!-- muss beantworten: Status API password incorrect, Zugangsdaten im Reiter Geräte über Verbindungseinstellungen ändern prüfen. -->

At startup the adapter sets `info._online` of all devices to `false`. It then reads address and credentials from the device objects and reconnects to every device. It does not need discovery for this. Until every device has answered, some are still offline.
<!-- quelle: code=src/main.ts:163-169@v2.0.0-beta.2; code=src/main.ts:248-285@v2.0.0-beta.2; code=src/main.ts:2011-2039@v2.0.0-beta.2; forum=608918; issue=#179 -->

If a device stays offline, check the tab "Devices" or `info._connectionStatus`:

| Status | Cause | Fix |
|---|---|---|
| `API password incorrect` | The device no longer accepts the password, e.g. since ESPHome 2026.1 | "Change connection settings", enter the key |
| `Encryption Key Missing` | The device now uses a key | same |
| `unreachable` | Device off or at another address | Check device and address |
<!-- quelle: code=src/main.ts:860-886@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:405-432@v2.0.0-beta.2; issue=#66; issue=#189 -->

If the address has changed, delete the device in the tab "Devices" and add it at the new address. A fixed address in the router prevents this.
<!-- quelle: code=src/lib/deviceManagement.ts:117-118@v2.0.0-beta.2; forum=648291 -->

**See also:** [API password and ESPHome 2026.1](../01.erste-schritte/03.erstes-geraet.md#api-password-still-work-esphome)

<a id="device-disconnect-every-few-seconds"></a>

## Why does my device disconnect every few seconds?

<!-- abschnitt: prio=B; gewicht=3; readme=missing; cluster=connection-setup-09; features=connection-behavior-settings,dashboard-version-select,logging-connection-errors -->
<!-- muss beantworten: Ping-Einstellungen und WLAN prüfen; was im Log steht. -->

The adapter pings every connected device at the ping interval. If as many answers are missing as set in "Ping attempts before offline", it drops the connection and re-establishes it. With the default of one attempt, a single lost ping is enough on weak Wi-Fi. The log then repeatedly shows `Connection to device <IP> lost …` and `ESPHome client … disconnected`.
<!-- quelle: code=src/main.ts:368-372@v2.0.0-beta.2; code=admin/jsonConfig.json5:220-248@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/connection.js:85-96@1.3.7; issue=#322; issue=#394 -->

1. In the main settings under "Connection behavior for known devices", set "Ping attempts before offline" to `3`.
2. Check the Wi-Fi signal of the device, e.g. with a `wifi_signal` sensor.
3. If that does not help, set `power_save_mode: none` under `wifi:` in the YAML and flash again.
<!-- quelle: code=admin/jsonConfig.json5:236-248@v2.0.0-beta.2; extern=esphome.io/components/wifi; issue=#324 -->

**See also:** [Connection settings](../03.referenz/01.einstellungen.md#reconnect-settings-exist-happens-device)

<a id="device-initialisation-needed-object-tree"></a>

## Why is there a device "Initialisation needed" in the object tree?

<!-- abschnitt: prio=B; gewicht=1; readme=missing; cluster=connection-setup-18; features=device-add-update-sendto,info-device-online -->
<!-- muss beantworten: Platzhalter für ein hinzugefügtes, nie erreichtes Gerät; Adresse und Schlüssel im Reiter Geräte prüfen, danach löschen. -->

"Initialisation needed" is the placeholder name of a device you added that never answered. The adapter only learns the real name on the first connection. Until then it writes the status of the attempt under `esphome.0.Initialisation needed.info`.
<!-- quelle: code=src/lib/helpers.ts:50-66@v2.0.0-beta.2; code=src/main.ts:358-365@v2.0.0-beta.2; code=src/main.ts:2134-2180@v2.0.0-beta.2; issue=#541 -->

1. Check address and key in the tab "Devices". The device is listed there by its address.
2. Delete the entry and add the device again with the correct data.
3. If the folder "Initialisation needed" is still in the tab "Objects" afterwards, delete it there.
<!-- quelle: code=src/lib/deviceManagement.ts:251-331@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:441-456@v2.0.0-beta.2; code=src/main.ts:1684-1702@v2.0.0-beta.2 -->

After a restart of the instance the adapter no longer tries such a device, because it never saved it as a device.
<!-- quelle: code=src/main.ts:248-285@v2.0.0-beta.2; code=src/main.ts:493-533@v2.0.0-beta.2 -->
