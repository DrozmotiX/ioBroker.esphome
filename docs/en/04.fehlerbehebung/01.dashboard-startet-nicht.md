## Why does the dashboard not start, and what does the log say?

<!-- abschnitt: prio=A; gewicht=20; readme=missing; cluster=dashboard-01; features=dashboard-pillow-version,dashboard-version-select,migration-pinned-versions,dashboard-enable -->
<!-- muss beantworten: Startprotokoll und Log lesen, die typischen Meldungen und was jeweils hilft, feste ESPHome-Version mit Auto Detect für Pillow und Device Builder. -->

The start log in the ESPHome tab shows the reason, the same messages are in the instance log. Most often the selected version cannot be installed. A fixed ESPHome version such as `2026.6.5` with "Auto Detect" for Pillow and Device Builder helps.
<!-- quelle: code=src/lib/dashboard.ts:248-265@v2.0.0-beta.2; code=admin/jsonTab.json5:44-73@v2.0.0-beta.2; code=io-package.json:187-189@v2.0.0-beta.2; forum=1315239; forum=1332264 -->

| Message | Meaning | What to do |
|---|---|---|
| "Fatal error starting ESPHomeDashboard" | The installation failed, often because pip cannot resolve the version combination. | Reset the versions as described below. |
| "ESPHome Dashboard could not be started, "…" is missing in the Python environment" | The Python environment is incomplete. | Reset the Python environment, see [below](#clear-autopy-cache-if-python). |
| "ESPHome Dashboard stopped (exit code …)" | The dashboard ended after starting. | The `[ESPHome - Console]` lines before it name the reason, see the [next section](#log-only-say-esphome-dashboard). |
| "ESPHome Dashboard container … was not created" | Docker is missing, not running, or the image could not be pulled. | Check Docker or turn off "Use Docker Integration (Beta)". |
<!-- quelle: code=src/lib/dashboard.ts:587-591@v2.0.0-beta.2; code=src/lib/dashboard.ts:658-683@v2.0.0-beta.2; code=src/lib/dashboard.ts:802-808@v2.0.0-beta.2; forum=1126697; forum=1221563 -->

### How to do it

1. Open the instance settings, tab "ESPHome Dashboard".
2. Set "ESPHome Dashboard version" to `2026.6.5` or to the version that ran last.
3. Under "Advanced", set "Pillow version" and "ESPHome Device Builder version" to "Auto Detect".
4. Save. The instance restarts and installs the versions.
5. It worked when the start log shows "ESPHome Dashboard is reachable on port …" and the dashboard appears in the tab.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=admin/jsonConfig.json5:538-562@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:88-107@v2.0.0-beta.2; code=src/lib/dashboard.ts:1182-1183@v2.0.0-beta.2; forum=1317187; forum=1322645 -->

If it still does not start, the Python environment is often damaged, for example after an interrupted download: [How do I reset the Python environment?](#clear-autopy-cache-if-python)
<!-- quelle: code=src/lib/dashboard.ts:1090-1108@v2.0.0-beta.2; forum=1237549; forum=1254323 -->

## What to do about "Please install the pillow python package"?

<!-- abschnitt: prio=B; gewicht=8; readme=partial; cluster=dashboard-02; features=dashboard-pillow-version,dashboard-enable,dashboard-clear-autopy-cache -->
<!-- muss beantworten: Pillow-Version auf Auto Detect stellen, sonst Python-Umgebung zurücksetzen und Instanz neu starten. -->

Do not install anything on the system. The dashboard runs in the adapter's own Python environment and does not see a Pillow you install with the package manager or pip.
<!-- quelle: code=src/lib/dashboard.ts:540-591@v2.0.0-beta.2; forum=1080009; forum=1270881; issue=#188 -->

1. Open the section "Advanced" in the tab "ESPHome Dashboard".
2. Set "Pillow version" to "Auto Detect". The adapter then installs the Pillow that fits the selected ESPHome version. A fixed version must fit ESPHome, otherwise Pillow is missing.
3. Save. The instance restarts and sets up the environment.
4. If the message keeps coming, reset the Python environment.
<!-- quelle: code=admin/jsonConfig.json5:538-550@v2.0.0-beta.2; code=io-package.json:188@v2.0.0-beta.2; code=src/lib/dashboardRequirements.ts:40-56@v2.0.0-beta.2; forum=633144; forum=726998 -->

With "Use Docker Integration (Beta)" the field does not exist, the ESPHome image brings its own Pillow.
<!-- quelle: code=admin/jsonConfig.json5:548@v2.0.0-beta.2; code=README.md:231-233@v2.0.0-beta.2 -->

**See also:** [Reset the Python environment](#clear-autopy-cache-if-python) · [Choose the dashboard version](../02.anleitungen/03.dashboard-nutzen.md#choose-update-esphome-dashboard-version)

## Why does the dashboard stop after a new ESPHome version?

<!-- abschnitt: prio=A; gewicht=9; readme=missing; cluster=dashboard-04; features=dashboard-version-select,dashboard-pillow-version,migration-pinned-versions,dashboard-enable,logging-misc-messages -->
<!-- muss beantworten: Grund im Log mit [ESPHome - Console] finden, auf die zuletzt laufende Version zurückstellen, Pillow auf Auto Detect. -->

The new version cannot be installed or started on your system. The adapter logs the reason as an error with `[ESPHome - Console]`, right before "ESPHome Dashboard stopped (exit code …)". Go back to the version that ran last.
<!-- quelle: code=src/lib/dashboard.ts:644-661@v2.0.0-beta.2; issue=#463; issue=#479; forum=1351814 -->

### How to do it

1. Open the instance settings, tab "ESPHome Dashboard".
2. If "ESPHome Dashboard version" shows "Always last available" or the new version, enter the version that ran last, or `2026.6.5`.
3. Check under "Advanced" that "Pillow version" is set to "Auto Detect".
4. Save. The instance restarts and installs the version. This takes a few minutes.
5. It worked when no further "ESPHome Dashboard stopped" follows in the log.
<!-- quelle: code=admin/jsonConfig.json5:394-406@v2.0.0-beta.2; code=admin/jsonConfig.json5:538-550@v2.0.0-beta.2; code=src/lib/dashboard.ts:405-413@v2.0.0-beta.2; forum=1349300; forum=1301427 -->

Regular dashboard messages only show in the log at log level "debug". Errors always appear.
<!-- quelle: code=src/lib/dashboard.ts:644-656@v2.0.0-beta.2 -->

**See also:** [How do I choose or update the ESPHome dashboard version, including older ones?](../02.anleitungen/03.dashboard-nutzen.md#choose-update-esphome-dashboard-version)

## How do I reset the Python environment when it is broken?

<!-- abschnitt: prio=B; gewicht=7; readme=missing; cluster=dashboard-06; features=dashboard-clear-autopy-cache,info-clear-autopy-button,dashboard-enable -->
<!-- muss beantworten: Button "Python-Umgebung zurücksetzen" unter dem Dashboard-Reiter, danach Instanz neu starten; ESPHome wird neu installiert, YAML-Dateien bleiben; bei Docker-Integration nicht sichtbar. -->

"Reset Python environment" deletes the Python environment of the dashboard with ESPHome, Device Builder, Pillow and everything that belongs to them. Your YAML files stay.
<!-- quelle: code=src/lib/dashboard.ts:1091-1108@v2.0.0-beta.2; code=admin/i18n/de.json:24@v2.0.0-beta.2; forum=1115918; forum=1315078 -->

1. Open the instance settings, tab "ESPHome Dashboard". The instance must be running.
2. Click "Reset Python environment" and confirm.
3. Restart the instance. It builds the environment again at startup. This needs internet and takes a few minutes.
<!-- quelle: code=admin/jsonConfig.json5:465-490@v2.0.0-beta.2; code=src/lib/dashboard.ts:1100-1102@v2.0.0-beta.2; code=src/lib/dashboard.ts:572-583@v2.0.0-beta.2 -->

It worked when the log shows `Starting ESPHome Dashboard` and the tab "ESPHome" shows the dashboard. Instead of the button you can also set `esphome.0.info.clearAutopyCache` to `true`.
<!-- quelle: code=src/lib/dashboard.ts:625-627@v2.0.0-beta.2; code=src/main.ts:206-217@v2.0.0-beta.2; code=src/main.ts:1747-1752@v2.0.0-beta.2; issue=#176; issue=#191 -->

With "Use Docker Integration (Beta)" the button is hidden, there is no Python environment then.
<!-- quelle: code=admin/jsonConfig.json5:473@v2.0.0-beta.2 -->
