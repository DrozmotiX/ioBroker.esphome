## Why does the dashboard tab not open ("localhost refused to connect")?

<!-- abschnitt: prio=A; gewicht=13; readme=partial; cluster=dashboard-11; features=dashboard-enable,dashboard-url-admin-tab,admin-tab-link,migration-dashboard-url -->
<!-- muss beantworten: Dashboard-Adresse und Port korrekt eintragen (ohne Port im IP-Feld), nicht localhost für Zugriff von außen, URL-Feld zuletzt bearbeiten, was der Tab beim Start und bei Fehlern zeigt. -->

Enter the address of your ioBroker host under "IP-Address where ESPHome Dashboard is running to integrate in ioBroker Admin", without a port. Do not use `localhost` or `127.0.0.1`.
<!-- quelle: code=admin/jsonConfig.json5:407-418@v2.0.0-beta.2; code=admin/jsonConfig.json5:582-596@v2.0.0-beta.2; forum=1340972; forum=1274190 -->

The tab shows the page under "URL of ESPHome Dashboard". Your browser loads this page, not the ioBroker host. `localhost` therefore points to the computer in front of you, and the browser reports "localhost refused to connect".
<!-- quelle: code=admin/jsonTab.json5:84-93@v2.0.0-beta.2; code=io-package.json:165-167@v2.0.0-beta.2; issue=#98 -->

### How to do it

1. Open the instance settings, tab "ESPHome Dashboard".
2. Tick "Enable ESPHome Dashboard".
3. Pick an address of the ioBroker host from the list in the IP field. The list offers IPv4 and IPv6 addresses, a host name works too. Do not add a port, the adapter adds it itself.
4. Under "Advanced" you find "Port of ESPHome Dashboard", default `6052`. Below it, "URL of ESPHome Dashboard" fills in by itself, e.g. `http://192.168.x.y:6052`. Enter your own URL last, because changing the IP or port overwrites it.
5. Save. The instance restarts.
6. Open the ESPHome tab in the admin menu. While the dashboard starts, it shows a hint and the start log. As soon as the dashboard answers, it appears by itself. On the first start this takes a few minutes.

<!-- bild: screenshot tab "ESPHome Dashboard" with checkbox, IP selection and expanded "Advanced" section with port and URL -->

If the tab shows a text instead of the dashboard, the text names the reason: instance not running, dashboard not enabled, no URL entered, or start failed. For the last case see [Why does the dashboard not start?](../04.fehlerbehebung/01.dashboard-startet-nicht.md#dashboard-not-start-pillow-esphome).
