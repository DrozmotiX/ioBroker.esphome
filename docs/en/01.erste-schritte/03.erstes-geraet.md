## How do I add an ESPHome device in the adapter?

<!-- abschnitt: prio=B; gewicht=5; readme=covered; cluster=connection-setup-01; features=device-add-update-sendto,device-ip-dropdown,requirements-esphome-api,device-credentials-storage -->
<!-- muss beantworten: Schritt für Schritt: api-Eintrag in der YAML, im Reiter Geräte über Gerät hinzufügen IP-Adresse oder Hostname und Schlüssel eintragen, Gerät erscheint online. -->

You add a device in the tab "Devices" of the instance settings. The instance must be running.
<!-- quelle: code=admin/jsonConfig.json5:255-280@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:160-176@v2.0.0-beta.2 -->

1. Check that the device YAML contains `api:` and copy the key under `api:` → `encryption:` → `key:`.
2. Open the instance settings and the tab "Devices".
3. Click "Add device".
4. Enter the IP address or host name of the device and the encryption key. You only need "API password (legacy)" for devices without a key on ESPHome before 2026.1. If the API is not protected, leave both fields empty.
5. Confirm. The adapter connects and shows the result within 30 seconds.
<!-- quelle: code=src/lib/deviceManagement.ts:378-396@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:467-513@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:521-546@v2.0.0-beta.2 -->

It worked when you see "OK - Device successfully connected, initializing configuration". The device is then in the group "Added devices", its states under `esphome.0.<device>`. If the device does not answer within 30 seconds, the adapter keeps trying in the background.
<!-- quelle: code=src/main.ts:405-421@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:495-501@v2.0.0-beta.2; code=src/i18n/de.json:32@v2.0.0-beta.2; code=src/i18n/de.json:38@v2.0.0-beta.2 -->

If discovery has already found the device, it is in the group "Discovered, not added yet". Click "Add" there, the address is already filled in.
<!-- quelle: code=src/lib/deviceManagement.ts:338-369@v2.0.0-beta.2 -->

**See also:** [Key not accepted](#encryption-key-not-accepted) · [No states in the object tree](#no-datapoints-shown-object-tree) · [Device discovery](../02.anleitungen/01.geraete-entdecken.md#auto-discovery-report-routers-foreign)

## Where do I enter the API password and does it still work with ESPHome 2026.1?

<!-- abschnitt: prio=B; gewicht=4; readme=covered; cluster=connection-setup-06; features=device-credentials-storage,device-add-update-sendto,default-credentials,requirements-esphome-api -->
<!-- muss beantworten: Das Feld API-Passwort (veraltet) im Dialog des Geräts gilt nur für ältere ESPHome-Versionen, ab 2026.1 zählt nur der Verschlüsselungsschlüssel. -->

You enter the API password in the device dialog in the field "API password (legacy)", when adding the device or via "Change connection settings". It is the password from `api:` → `password:` in the YAML, not the OTA password.
<!-- quelle: code=src/lib/deviceManagement.ts:274@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:537-541@v2.0.0-beta.2; forum=733214; forum=803715 -->

From ESPHome 2026.1 on there is no API password any more, only the encryption key works. If the dialog contains a key, the adapter uses only the key and ignores the password.
<!-- quelle: code=admin/i18n/de.json:33@v2.0.0-beta.2; code=src/main.ts:1633-1660@v2.0.0-beta.2; code=src/main.ts:391-398@v2.0.0-beta.2; issue=#410 -->

If the device rejects the password, the log shows `Device <IP> rejected the API password` and `info._connectionStatus` of the device reads `API password incorrect`.
<!-- quelle: code=src/main.ts:871-878@v2.0.0-beta.2 -->

**See also:** [Key not accepted](#encryption-key-not-accepted)

## Why is my encryption key not accepted?

<!-- abschnitt: prio=B; gewicht=3; readme=partial; cluster=connection-setup-03; features=device-credentials-storage,device-add-update-sendto,logging-connection-errors,default-credentials -->
<!-- muss beantworten: Wo der Schlüssel pro Gerät steht (Verbindungseinstellungen ändern), wie Encryption Key Missing aussieht, Handshake failure bei falschem Schlüssel. -->

You enter the key per device in the tab "Devices", when adding it or via "Change connection settings". It is in the YAML under `api:` → `encryption:` → `key:`. Copy it without quotation marks.
<!-- quelle: code=src/lib/deviceManagement.ts:270-278@v2.0.0-beta.2; code=src/lib/deviceManagement.ts:405-432@v2.0.0-beta.2; forum=1319795 -->

The log tells you what does not match:

| In the log | Status of the device | Meaning |
|---|---|---|
| `Device <IP> requires an encryption key, …` | `Encryption Key Missing` | The device requires a key, the adapter has none. |
| `ESPHome client <IP> … Handshake failure` | changes with every attempt | The key does not match the device. |
<!-- quelle: code=src/main.ts:878-886@v2.0.0-beta.2; code=src/main.ts:915-917@v2.0.0-beta.2; code=node_modules/@2colors/esphome-native-api/lib/utils/noiseFrameHelper.js:121@1.3.7; issue=#194 -->

If the key does not match, open "Change connection settings" of the device and enter the key from the YAML currently flashed. If you leave both fields empty, the adapter keeps the stored credentials.
<!-- quelle: code=src/lib/deviceManagement.ts:411-431@v2.0.0-beta.2; forum=1313904 -->

**See also:** [Other messages of the library](../03.referenz/06.log-meldungen.md#deserializebinary-assertion-failed-bad-format) · [Find the stored key](../02.anleitungen/02.geraete-verwalten.md#recover-stored-masked-api-password)
