## How do I install an older version or a pre-release?

<!-- abschnitt: prio=B; gewicht=9; readme=partial; cluster=logs-install-04; features=requirements-runtime -->
<!-- muss beantworten: Schritte für Installation einer bestimmten Version, Vorabversion oder per GitHub-URL inklusive Update-Hinweis. -->

You install pre-releases and older versions on the console of the ioBroker host. The ioBroker repository does not offer pre-releases.
<!-- quelle: code=README.md:185-210@v2.0.0-beta.2; forum=1278359 -->

| Goal | Command |
|---|---|
| current pre-release | `iobroker url iobroker.esphome@next` |
| a specific version | `iobroker url iobroker.esphome@2.0.0-beta.2` |
| back to the released version | `iobroker url iobroker.esphome` |
<!-- quelle: code=README.md:191-206@v2.0.0-beta.2 -->

All versions with their changes are listed under [Releases](https://github.com/DrozmotiX/ioBroker.esphome/releases). The instance and its settings stay when you switch. If you install the adapter this way for the first time, ioBroker creates no instance. Then add it yourself in admin, tab "Adapters".
<!-- quelle: code=README.md:208-209@v2.0.0-beta.2; forum=1272717; issue=#187 -->

## Why does the instance stay red after install or update?

<!-- abschnitt: prio=B; gewicht=6; readme=missing; cluster=logs-install-07,logs-install-15; features=dashboard-enable,requirements-runtime,dashboard-url-admin-tab -->
<!-- muss beantworten: Instanz ist grün, solange sie läuft (info.connection); rot heißt, sie läuft nicht; Ursache im Log; verbundene Geräte in info.connectedDevices. -->

The instance is green while the adapter runs. This is `esphome.0.info.connection`. Whether devices are connected does not change it. The connected devices are listed in `esphome.0.info.connectedDevices`.
<!-- quelle: code=src/main.ts:141-146@v2.0.0-beta.2; code=src/main.ts:2182-2193@v2.0.0-beta.2; code=src/lib/connectionState.ts:13-35@v2.0.0-beta.2 -->

If the instance stays red, the adapter is not running. The reason is in the log of the instance:

1. Open the tab "Log" in admin and filter for `esphome.0`.
2. If it mentions the Node.js version, install Node.js 22.19 or newer.
3. If it shows an error while loading the adapter, install it again, e.g. with `iobroker url iobroker.esphome`, and start the instance.
<!-- quelle: code=package.json:29-31@v2.0.0-beta.2; forum=755861; forum=589822; issue=#177 -->

A dashboard that does not start does not turn the instance red. The error is then in the log and the reason in the tab "ESPHome Dashboard".
<!-- quelle: code=src/lib/dashboard.ts:586-591@v2.0.0-beta.2; code=src/lib/dashboard.ts:686-700@v2.0.0-beta.2; code=admin/jsonTab.json5:37-66@v2.0.0-beta.2 -->

**See also:** [Why does the dashboard not start?](../04.fehlerbehebung/01.dashboard-startet-nicht.md#dashboard-not-start-pillow-esphome)

## Why can the adapter not be installed or compiled after restoring a backup?

<!-- abschnitt: prio=B; gewicht=2; readme=missing; cluster=logs-install-18; features=dashboard-enable,dashboard-clear-autopy-cache -->
<!-- muss beantworten: Was nach einer Wiederherstellung neu aufgebaut werden muss (Python-Umgebung zurücksetzen, Instanz neu starten). -->

A restore brings back the settings and states. ioBroker installs the adapter again, possibly in an older version. The Python environment of the dashboard lives outside ioBroker and is not part of the backup.
<!-- quelle: code=src/lib/dashboard.ts:1091-1095@v2.0.0-beta.2; forum=1278207; forum=955184 -->

This gets everything running again:

1. Check the installed version in admin, tab "Adapters". If it is old, install the current one, e.g. with `iobroker url iobroker.esphome`.
2. If the dashboard does not start, press "Reset Python environment" in the tab "ESPHome Dashboard" and restart the instance. The adapter builds the environment again at startup.
3. Check in the tab "Devices" that all devices are connected.
<!-- quelle: code=src/lib/dashboard.ts:1096-1108@v2.0.0-beta.2; code=admin/jsonConfig.json5:466-490@v2.0.0-beta.2; code=src/main.ts:248-285@v2.0.0-beta.2 -->
